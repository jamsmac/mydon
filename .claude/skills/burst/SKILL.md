# /burst — веер, который заканчивается выбором

Веер нужен там, где дешевле показать три непохожих решения, чем спорить об одном. Но веер — не отказ
от решения: он всегда заканчивается одним выбором с причиной. Владельцу не отдают «А/Б/В» без рекомендации.

## Когда

- Экран, карточка, лента, пустое состояние — форма ещё не выбрана.
- Текст, который увидит человек: сообщение бота, письмо, пункт ТЗ, формулировка вопроса владельцу.
- Подход к задаче, где развилка дешёвая на бумаге и дорогая в коде (где взять данные, чем считать, кто владелец шага).

Не нужен, когда решение уже принято (тогда `/devil`) или когда неясен сам scope (тогда `/align`).

## Шаги

1. **Одна строка задачи** и **критерий выбора**: по чему сравниваем (скорость, риск, объём работ,
   понятность владельцу). Без критерия веер превращается в вкусовщину.
2. **Сделать N вариантов**: по умолчанию **3**, максимум **5**, минимум 2. Каждый отличается **осью**
   — целью, структурой, объёмом работ или риском, — а не оформлением.
3. **Экраны — только через `/mydon-design`**: ASCII-макет прямо в ответе или файл `design/<slug>-<n>.html`
   на существующих токенах. Новые токены не заводить, оранжевая заливка — не больше одной.
4. **Тексты — целиком**, в готовом виде (сообщение, письмо, пункт), а не пересказ «примерно так».
5. **Отбраковать клоны**: если два варианта отличаются словом или цветом кнопки — оставить один и
   добить веер настоящей альтернативой либо честно выдать меньше вариантов.
6. **Выбрать**: «выбираю №, потому что …» — и одной строкой, чем платим за отказ от остальных.
7. Если выбор принципиальный (навигация, схема данных, деньги) — `docs/decisions/YYYY-MM-DD-<slug>.md`
   с причиной и строка в `memory/decisions.md`.

## Формат

```
Задача: … · Выбираем по: …
| № | Тезис (одна строка) | Чем отличается | Чего стоит |
|---|---------------------|----------------|------------|
| 1 | …                   | …              | …          |
| 2 | …                   | …              | …          |
| 3 | …                   | …              | …          |
Выбираю №N, потому что … Отказ от остальных стоит: …
Макеты: design/<slug>-1.html … / ASCII выше / тексты выше
```

## Чего не делать

- Не давать варианты-клоны: другой цвет, другой заголовок, переставленные блоки — это один вариант.
- Не превышать 5 вариантов — веер шире пятерых не читают, он перекладывает работу на владельца.
- Не заканчивать без выбора: список без рекомендации — невыполненная работа.
- Не рисовать экраны мимо `/mydon-design` и не изобретать токены ради «варианта поинтереснее».
- Не выдумывать факты ради разнообразия: цены, сроки, остатки — из Core и файлов, иначе вариант помечается «гипотеза».
- Не нарушать ради варианта `memory/constraints.md` (тиры, личный контур, два уровня навигации).
