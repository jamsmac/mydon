# /devil — возражение с ценой ошибки

Правило репозитория: у каждого решения записана причина (`docs/decisions/`). Причина проверяется не
согласием, а попыткой её сломать. Навык ломает решение дёшево — на словах, — чтобы оно не сломалось
дорого в проде.

**Главное правило: возражение без цены ошибки не считается.** «Мне не нравится» — не возражение.

## Когда обязателен

- Шаг необратим или дорого откатывается: миграция, снос таблицы, смена источника истины, катовер, деплой на прод.
- Задеты деньги, договоры, публикации от имени владельца, порог автономии (`AGENT_AUTONOMY_MAX`, тиры T3–T4).
- Решение принято по ощущению: в сессии нет ни одного проверенного факта в его пользу.
- Перед записью файла в `docs/decisions/` — чтобы причина пережила возражение, а не появилась после аварии.

## Шаги

1. **Назвать решение одной строкой** — так, как его подписал бы владелец. Строка не складывается —
   решения ещё нет: сначала `/align`, потом сюда.
2. **Собрать факты**: `memory/constraints.md`, `docs/decisions/`, роутер направления (`routers/*.md`), код.
   Возражение опирается на файл или на замер, не на впечатление.
3. **Выписать 3–5 возражений**, каждое ровно тремя полями:
   - **что сломается** — конкретный сценарий с именами файлов/таблиц/экранов, а не «риск качества»;
   - **во сколько обойдётся** — часы, деньги, простой, потерянные данные, ручной разбор;
   - **как проверить дёшево** — запрос к настоящей базе, тест, замер на настоящем входе, один звонок.
   Возражение без третьего поля — не возражение, а строка в `memory/open-questions.md`.
4. **Сложить возражения по цене** и выдать **вердикт одной строкой**: `делать` · `переделать` · `отложить`
   — с одной причиной. Вердикт обязателен даже когда все возражения слабые.
5. Если решение принципиальное — файл `docs/decisions/YYYY-MM-DD-<slug>.md` (решение · причина ·
   что рассматривали · чем рискуем) и строка в `memory/decisions.md`.

## Формат

```
Решение: … (одна строка, как подписал бы владелец)
Возражения:
  1. Сломается: … · Цена: … · Дешёвая проверка: …
  2. Сломается: … · Цена: … · Дешёвая проверка: …
  3. Сломается: … · Цена: … · Дешёвая проверка: …
Проверить не смогли: … / нет
Вердикт: делать | переделать | отложить — потому что …
Запись решения: docs/decisions/YYYY-MM-DD-<slug>.md / не требуется
```

## Чего не делать

- Не спорить с фактами из `memory/constraints.md` и `engine/autonomy.yaml`: инвариант — не мнение, а граница.
  Считаете границу неверной — это отдельное решение владельца, а не возражение внутри задачи.
- Не предлагать «варианты А/Б/В» вместо вердикта: правило владельца — одно решение с причиной.
  Веер альтернатив — это `/burst`, и он тоже заканчивается выбором.
- Не выдавать за возражение вкус, стиль или «так не принято» без цены ошибки.
- Не растягивать список: больше 5 возражений прячут главное; слабые уходят в `memory/open-questions.md`.
- Не смягчать вердикт, чтобы понравиться, и не менять его после «я всё-таки хочу» — менять только на новом факте.
