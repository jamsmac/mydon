# /onboard — бриф перед усилием

Цель: через 2–3 минуты знать ровно то, что нужно для задачи, и ничего лишнего. Роутеры — вместо
чтения дерева файлов; агент ищет по карте, а не по папкам.

## Вход

`/onboard <направление | задача | путь к файлу>`. Без аргумента — общий бриф по репозиторию.

## Шаги

1. **`CLAUDE.md`** — прочитать целиком (это роутер, он короткий): три слоя, направления, правила, карта, цели.
2. **Определить направление задачи** по таблице «Направления» и открыть **его роутер** `routers/<domain>.md`
   (для правок процесса/деплоя — `routers/dev.md`; для нового экрана — дополнительно навык `/mydon-design`).
   Если задача касается двух направлений — оба роутера, но не больше.
3. **`memory/constraints.md`** — инварианты; **`memory/decisions.md`** — последние 3–5 решений по теме,
   при необходимости открыть сам файл в `docs/decisions/`.
4. **`memory/open-questions.md`** — нет ли открытого вопроса ровно по этой задаче (если есть — сначала он).
5. **`memory/session-log/`** — последний файл, если он моложе 7 дней: активный контекст и «следующий шаг».
6. Открыть **только те файлы кода**, которые роутер называет для этой задачи (эталоны, спеки). Не сканировать `apps/` целиком.
7. Проверить состояние репозитория: `git status`, текущая ветка (не `main`!), незакоммиченное.

## Выход — бриф владельцу (≤ 15 строк)

```
Направление: … · Роутер: routers/….md
Задача как я её понял: …
Что уже есть по теме: … (файлы из роутера, 2–5 ссылок)
Ограничения, которые задевает: … (из constraints.md)
Последние решения по теме: … (даты + одна строка)
Открытые вопросы: … / нет
Предлагаю начать с: … (одно действие)
Неясно (спрошу до кода): … / нет
```

Если «Неясно» не пусто — дальше `/align`, не код.

## Правила

- Роутер устарел (в нём нет файла, который явно нужен)? Работать по факту, а в конце сессии `/calibrate`
  предложит правку роутера — не править молча.
- Не переписывать содержимое референсов в бриф — ссылки.
- Никаких действий с побочными эффектами на этом шаге: только чтение и `git status`.
