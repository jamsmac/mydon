# Сторожа сервера

Скрипты живут на сервере в `/opt/mydon-stock/`, здесь — их копии под контролем версий.
Раньше они существовали только на сервере: потеря диска означала потерю скриптов.

## Что переведено на MYDON

| Скрипт | Состояние | Что делает |
|---|---|---|
| `disk_guard.sh` | ✅ переведён | шлёт событие `infra.disk` в Core; решение о срочности принимают правила |
| `healthz_guard.sh` | ✅ переведён | проверка здоровья каждые 5 минут + отбой при восстановлении |
| `backup_offsite.sh` | ждёт | ночной бэкап + копия в Telegram |

## Принцип перевода

Вместо прямой отправки в Telegram скрипт шлёт событие:

```bash
curl -sf -m 15 -X POST "http://127.0.0.1:3001/ingest/${INGEST_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{"type":"infra.disk","source":"disk_guard","payload":{"usedPercent":74,"host":"hetzner"}}'
```

Пороги живут в правилах Core (`apps/core/src/rules/rules.ts`), а не в скрипте:
70–85% уходит в утреннюю сводку, 85%+ будит сразу.

## Обязательное правило: запасной путь

**Тревога об инфраструктуре не должна зависеть от той же инфраструктуры.**
Если Core не ответил, а показатель в красной зоне, скрипт шлёт сообщение
напрямую в Telegram — как делал раньше. Иначе при падении сервера некому
будет сообщить, что сервер упал.

### Что НЕ переносится в правила

Защита от спама остаётся В СКРИПТЕ. Core шлёт уведомление на каждое событие,
поэтому отправлять их каждые 5 минут означало бы 12 тревог в час. Сторож
здоровья сам решает, когда сказать: на 2-м провале подряд, дальше примерно
раз в час.

Там же остаётся различение слоёв: если Docker говорит «контейнер здоров»,
а `/healthz` недоступен с хоста, лежит сеть/Tailscale, а не приложение —
это разные действия для владельца.

Проверено подстановкой мёртвого адреса Core:
- MYDON недоступен + диск 91% → уходит напрямую;
- MYDON недоступен + диск 74% → молчит (не критично, будить незачем);
- диск 65% → выходит сразу.
