# Сторожа сервера

Здесь живут версии под контролем версий; исполняемые копии ставит деплой.
Раньше они существовали только на сервере: потеря диска означала потерю скриптов.

## Где что запускается

| Скрипт | Путь на сервере | Кто обновляет | Чей |
|---|---|---|---|
| `disk_guard.sh` | `/opt/backups/disk_guard.sh` | деплой mydon | mydon |
| `healthz_guard.sh` | `/opt/backups/healthz_guard.sh` | деплой mydon | mydon (наблюдает склад) |
| `backup_extra.sh` | `/opt/backups/backup_extra.sh` | деплой mydon | mydon |
| `b2_offsite.sh`, `db_access.sh` | `/opt/backups/` | деплой mydon | mydon |
| `backup_offsite.sh` | `/opt/mydon-stock/backup_offsite.sh` | вручную | **склад** |

`backup_offsite.sh` дампит базу СКЛАДА (`docker compose exec -T db pg_dump` из
каталога склада) и шлёт её ботом склада — это бэкап склада, а не mydon, и он
уходит вместе со складом в П8. Переселять его на пути mydon нечего: он всё
равно обращался бы к каталогу склада за compose-проектом и .env.

|---|---|---|

## Откуда берутся ключи

Сторожа mydon читают ТОЛЬКО окружение mydon. Лесенка одна на всех
(`backup_extra.sh`, `disk_guard.sh`, `healthz_guard.sh`):

1. `INGEST_KEY` из `/opt/mydon-app/.env` — событие в Core (журнал + правила);
2. `TG_BACKUP_BOT_TOKEN` / `TG_BACKUP_CHAT_ID` оттуда же — свой аварийный канал;
3. `WATCHDOG_BOT_TOKEN` / `WATCHDOG_CHAT_IDS` из `/etc/mydon-heartbeat.env` —
   фолбэк на аварийного бота сторожа (работает, но шумно).

Нет ни ключа Core, ни аварийного бота — сторож пишет причину в
`/opt/backups/backup.log` и выходит НЕНУЛЁМ, а не «успешно молчит». Так же
он поступает, если `df` не дал процент заполнения или у `healthz_guard.sh` не
задана цель (`HEALTHZ_TARGET` / `WEB_PORT`); а тревога, которую не принял ни
Core, ни Telegram, отдельной строкой попадает в тот же журнал. Проверка
делается до измерения диска и до первой проверки здоровья: сторож без
конфигурации молчал бы ровно до дня аварии, и в этот день молчал бы тоже.

## Принцип перевода

Вместо прямой отправки в Telegram скрипт шлёт событие:

```bash
curl -sf -m 15 -X POST "http://127.0.0.1:3001/ingest/${INGEST_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{"type":"infra.disk","source":"disk_guard","payload":{"usedPercent":74,"host":"hetzner"}}'
```

Пороги живут в правилах Core (`apps/core/src/rules/rules.ts`), а не в скрипте:
70–85% уходит в утреннюю сводку, 85%+ будит сразу.

## Обязательное правило: запасной путь

**Тревога об инфраструктуре не должна зависеть от той же инфраструктуры.**
Если Core не ответил, а показатель в красной зоне, скрипт шлёт сообщение
напрямую в Telegram — как делал раньше. Иначе при падении сервера некому
будет сообщить, что сервер упал.

### Что НЕ переносится в правила

Защита от спама остаётся В СКРИПТЕ. Core шлёт уведомление на каждое событие,
поэтому отправлять их каждые 5 минут означало бы 12 тревог в час. Сторож
здоровья сам решает, когда сказать: на 2-м провале подряд, дальше примерно
раз в час.

Там же остаётся различение слоёв: если Docker говорит «контейнер здоров»,
а `/healthz` недоступен с хоста, лежит сеть/Tailscale, а не приложение —
это разные действия для владельца.

Проверено подстановкой мёртвого адреса Core:
- MYDON недоступен + диск 91% → уходит напрямую;
- MYDON недоступен + диск 74% → молчит (не критично, будить незачем);
- диск 65% → выходит сразу.

## Переселение с путей склада (П8.2)

До 08.2026 `disk_guard.sh` и `healthz_guard.sh` запускались по cron из
`/opt/mydon-stock/` и читали бота склада. Деплой mydon туда не заглядывает,
поэтому хостовая копия `disk_guard.sh` отстала от git на месяц, а переезд
склада унёс бы сторожей вместе с собой.

Расписание переводит идемпотентный установщик — один раз, вручную, после мержа:

```bash
/opt/mydon-app/deploy/setup-guards.sh --dry-run   # показать diff crontab
/opt/mydon-app/deploy/setup-guards.sh             # применить
```

Он меняет ТОЛЬКО строки сторожей mydon (расписание сохраняется), кладёт прежний
crontab в `/opt/backups/crontab_pre_guards_<дата>` и отказывается переводить
расписание на путь, по которому нет исполняемого файла.

## Откат

Оригинал сохранён на сервере: `/opt/mydon-stock/disk_guard.sh.bak-before-mydon`.
Прежнее расписание: `crontab /opt/backups/crontab_pre_guards_<дата>`.
