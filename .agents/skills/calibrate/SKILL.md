# /calibrate — сложить исправления в систему

Идея (RoboNuggets, модуль Calibrate): система накапливается, если каждое исправление владельца
оседает в файле, который прочитает следующая сессия. Иначе одно и то же объясняется каждый раз.

## Режимы

- `/calibrate lite` — 1–3 предложения, только самое ценное; 1 минута.
- `/calibrate` (full) — полный разбор сессии + handoff.
- `/calibrate auto` — то же, что full, но правки **малого риска** (роутеры, `memory/`, `session-log`) применяются
  сразу и показываются диффом; навыки агентов и `AGENTS.md` — только предложением. В MYDON по умолчанию — **не auto**:
  правки навыков агентов идут через согласование (как coach-diff), `AGENTS.md` меняется только с согласия владельца.

## Шаги

1. **Собрать исправления.** Пройти сессию и выписать каждое место, где владелец поправил, уточнил, отменил
   или сказал «не так». Формулировать как правило, а не как случай: «в VendHub аппарат = точка, второй справочник
   мест не заводим», а не «в этот раз не стал делать справочник».
2. **Классифицировать каждое** по адресу:
   | Тип | Куда |
   |---|---|
   | где что лежит, кого спрашивать, какие файлы читать | `routers/<domain>.md` (или `AGENTS.md` → карта, если сквозное) |
   | правило, которое нельзя нарушать | `memory/constraints.md` |
   | принятое решение с причиной | `docs/decisions/YYYY-MM-DD-<slug>.md` + строка в `memory/decisions.md` |
   | термин, который поняли не так | `memory/glossary.md` |
   | как должен работать навык Codex | `.Codex/skills/<skill>/SKILL.md` или его референс |
   | как должен работать навык агента | `apps/agents/agents/<agent>/skills/<skill>.md` — **только предложением**, применяет владелец или coach-diff |
   | вопрос без ответа | `memory/open-questions.md` |
   | цель изменилась / достигнута | `AGENTS.md` → «Цели» — предложением |
3. **Проверить на дубли**: то же правило уже записано? Тогда уточнить существующую строку, не добавлять вторую.
4. **Показать предложения диффами** (файл → было → стало, одна строка причины). Ничего не применять без «да»,
   кроме режима `auto` для файлов малого риска.
5. **Написать handoff** `memory/session-log/YYYY-MM-DD-<slug>.md` по шаблону из `memory/session-log/README.md`:
   активный контекст · сделано · ожидает · решения · исправления → куда легли · следующий шаг.
6. Если менялась структура навигации или правило дизайна — напомнить про запись в `docs/decisions/` с причиной
   (правило репозитория: решение без причины пересматривается вслепую).

## Чего не делать

- Не записывать в память «обстоятельства дня» (ветку, номер PR, временные цифры) — только то, что переживёт месяц.
- Не переписывать роутер целиком — точечная правка строки.
- Не менять `apps/agents/agents/*/skills/*.md` напрямую: их тир и `allowed-tools` — часть политики безопасности.
- Не смягчать правила безопасности (тиры, ledger, denylist) даже по просьбе «упростить».

## Выход

Список диффов (или «правок нет — сессия без исправлений») + путь к handoff.
