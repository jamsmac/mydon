# SKILL — qualify-lead

**Когда:** появился новый лид (входящий запрос, выставка, тендер).
**Тир автономии:** T1 (квалификация). Переход к КП — T3.

## Цель
Оценить лид и присвоить класс hot / warm / cold с следующим шагом.

## Вход
- Данные лида: компания, потребность, объём, отрасль, срочность, бюджет, контакт/ЛПР.
- KB: `heli-models.md`, `pricelist.md`.

## Шаги
1. Сопоставить потребность с линейкой HELI (FD/FG/CPD/G) — есть ли фит.
2. Оценить сигналы (каждый 0–2): бюджет, срочность, объём, доступ к ЛПР, соответствие модели.
3. Сумма → класс:
   - **hot** ≥ 8 и есть бюджет+срочность,
   - **warm** 4–7,
   - **cold** < 4 или нет ЛПР/бюджета.
4. Определить следующий шаг (КП / звонок / прогрев).
5. Записать в `tasks` + (если hot и фит понятен) предложить перейти к черновику КП — это уже T3.

## Выход / формат
```
Лид: <компания>
Потребность: <N× модель — отрасль>
Класс: <hot|warm|cold> (score N)
Сигналы: бюджет ?, срочность ?, объём ?, ЛПР ?, фит ?
Следующий шаг: <...>
```

## Правила и edge-cases
- Нет фита по модели → честно cold, не натягивать.
- Цена — только из `pricelist.md`. Нет позиции в прайсе → не выдумывать, эскалация.
- КП никогда не уходит клиенту из этого скилла — только черновик на кнопку.

## Эскалация
Нестандартная конфигурация/скидка/условия оплаты → человеку.
