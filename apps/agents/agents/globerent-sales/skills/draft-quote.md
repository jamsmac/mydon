# SKILL — draft-quote

**Когда:** есть hot-лид с понятным фитом (после `hunt-leads`/`qualify-lead`). **Тир:** T3 (деньги → кнопка).

## Цель
Собрать черновик КП из реальных данных: модель(и) HELI, кол-во, цены ИЗ ПРАЙСА, условия.

## Вход
- Лид: компания, потребность, объём, регион, контакт.
- KB: `pricelist.md` (цены — ТОЛЬКО отсюда), `heli-models.md`, `clients.md`.

## Шаги (v2)
1. Подобрать модель(и) HELI под потребность (`heli-models.md`).
2. Взять цену (`priceUzs`, целое число сум С НДС) ТОЛЬКО из `pricelist.md` по конкретным позициям.
3. Если позиции НЕТ в прайсе или прайс пуст → НЕ выдумывать цену: позицию НЕ включать в JSON, отметить в `note` соседней позиции/в тексте, что КП НЕПОЛНОЕ.
4. Сформировать до 3 вариантов комплектации: `budget` (база) / `optimal` (рекомендуемая) / `premium` (полная) — позиции и цены только из прайса.
5. Подтянуть курс USD/UZS из контекста `scan-fx` (memory_facts). Если нет — рантайм возьмёт сам.
6. Вернуть СТРОГО JSON (ниже). **Итоги/НДС НЕ считать — это делает код.** Рантайм отрендерит PDF ×N и отправит на кнопку одобрения T3 с файлами. Клиенту сам не уходит.

## Выход / формат (строгий JSON, без прозы вокруг)
```json
{
  "client": { "name": "<компания>", "inn": "<ИНН|опц>", "contact": "<телефон|опц>" },
  "validUntil": "<YYYY-MM-DD>",
  "currencyRate": { "usdUzs": <число>, "date": "<YYYY-MM-DD>" },
  "variants": [
    { "variant": "budget",  "items": [ { "model": "<точное имя из прайса>", "qty": <N>, "priceUzs": <целое из прайса>, "note": "<опц>" } ] },
    { "variant": "optimal",  "items": [ ... ] },
    { "variant": "premium",  "items": [ ... ] }
  ]
}
```
Если уверенный вариант один — допускается `{ "client", "validUntil", "currencyRate", "items": [...] }` (рантайм отрендерит как `optimal`).

## Правила (жёстко)
- Любая цена/скидка вне `pricelist.md` → выдумывать ЗАПРЕЩЕНО (позицию не включать), эскалация.
- `priceUzs` — целое число сум из прайса; итоги и НДС 12% считает рантайм, не модель.
- КП НИКОГДА не уходит клиенту из скилла — только черновик на одобрение (T3).
- Договор — это T4 (отдельно); здесь только КП.

## Эскалация
Нестандартные скидки/условия/рассрочка → человеку (T3+), не решать самому.

## Follow-up
После JSON можно добавить блок `NEXT:` с подсказками (F0.5), напр. `NEXT: после одобрения — оформить договор (T4); зафиксировать сделку в EAV`. Платформа их покажет.
