# SKILL — monitor-stock

**Когда:** cron 08:00 (полный прогон) и */30 (быстрый: нули/аномалии).
**Тир автономии:** T0 (мониторинг) → T1 (заявка/маршрут).

## Цель
Знать состояние всех 31 автоматов, заранее предупредить дефицит, поймать аномалии.

## Вход
- `machines-map.md` — список машин, типы, пороги, вместимость.
- `thresholds.md` — нормы (< 30% пополнить, < 20%/2ч аномалия).
- Данные продаж/остатков (телеметрия или ручной ввод — пока источник уточняется).

## Шаги
1. По каждой машине взять текущий остаток и средний темп продаж.
2. Посчитать «дней до нуля» = остаток / средний дневной расход.
3. Пометить: 🔴 ≤ 1–2 дней (критично), 🟡 < 30% (пополнить), ✅ норма.
4. Для < 30% — сформировать заявку на пополнение (T1).
5. Быстрый прогон */30: найти машины с продажами < 20% среднего > 2ч → аномалия.
6. Если на пополнение ≥ 2 машин — предложить маршрут объезда (кратчайший по локациям).
7. Записать отчёт в `tasks`/трейс; отдать сводку chief-of-staff к 09:00.

## Выход / формат
```
VENDHUB · <дата>
🔴 Критично: #<id> <локация> — <N> дн
🟡 Пополнить: #.., #.. (< 30%)
✅ Норма: <N> машин
Аномалии: #<id> — продажи <%> за <ч>
Маршрут: #.. → #.. → #..
```

## Правила и edge-cases
- Нет данных по машине → пометить «нет данных», не считать как 0.
- Пороги — только из `thresholds.md`.
- Заявка не равна закупке: закупку подтверждает человек/Бехруз.

## Эскалация
Критично (≤ 1 дня), повторная аномалия по одной машине, подозрение на сбой купюрника/инкассации → человеку.

## Happy-path
Прочитать остатки (EAV/телеметрия) → посчитать дни-до-нуля → при <30% сформировать заявку (T1) → маршрут. Вернуть структурный отчёт.

## Error-path
Нет данных по машине → пометить «нет данных», НЕ считать 0. Сбой источника → запросить свои трейсы (getChain по correlation_id), сообщить что именно недоступно, эскалировать оператору. Не выдумывать остатки.

## Break-glass
Прямое изменение остатков/принудительная заявка вне порогов — только через одобрение человека (HITL) + полный аудит. По умолчанию запрещено.
