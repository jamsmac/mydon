# SKILL — draft-service-reply

**Когда:** есть конкретное обращение, требующее ответа клиенту (после `triage-service`). **Тир:** T3 (исходящее клиенту → кнопка).

## Цель
Собрать черновик ответа клиенту: подтвердить приём, обозначить тип, следующий шаг и срок — из реальных данных, без обещаний по деньгам/гарантии.

## Вход
- Обращение: клиент, модель HELI, тип, описание, срочность, контакт.
- KB: `faq.md`, `heli-models.md`, `service-criteria.md`.

## Шаги
1. Определить тип и приоритет (из обращения / `service-criteria.md`).
2. Сформулировать ответ: подтверждение приёма → что поняли → следующий шаг → ориентировочный срок реакции.
3. Если нужны данные, которых нет (цена/наличие запчасти, решение по гарантии) → НЕ выдумывать: «уточним и сообщим отдельно», пометить обращение на эскалацию.
4. Тон деловой, по делу, без обязательств по сумме/гарантии.
5. Отдать ЧЕРНОВИК на кнопку одобрения (T3). Клиенту сам не отправляет.

## Выход / формат
```
Ответ клиенту (черновик) — <клиент> · обращение #<id>
Тема: сервис <модель> — <тип>
Текст:
  <приветствие>, приняли ваше обращение по <суть>.
  <следующий шаг>. Ориентировочный срок: <срок>.
  <если нужны данные: уточним цену/наличие/гарантию и сообщим отдельно>
Статус: ЧЕРНОВИК → одобрение (клиенту не отправлено)
```

## Правила
- Никаких цен/сроков-обязательств/гарантийных решений без человека — только «уточним».
- Только факты из KB; неуверенное — «уточним», не выдумывать.
- Ничего не отправляется автоматически (advisory).

## Эскалация
Гарантия, стоимость, нестандартные условия → владельцу до ответа клиенту.
