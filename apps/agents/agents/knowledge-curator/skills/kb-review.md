# SKILL — kb-review

**Когда:** cron каждые 7 дней; либо по сигналу «данные неактуальны».
**Тир автономии:** T2 (diff + автокоммит через 24ч), T3 для цен/договоров.

## Цель
Найти устаревшие или противоречивые данные в KB и предложить правки.

## Вход
- Страницы `shared/kb/**`.
- `index.md` с датами `updated`.
- Трейсы с пометками о неактуальности.

## Шаги
1. Пройти страницы, отсортировать по дате обновления (самые старые — первыми).
2. Для каждой проверить признаки устаревания: дата > порога, помеченные `TODO`, противоречия между страницами.
3. Где есть надёжный источник — подготовить diff. Где нет — пометить `требует подтверждения`.
4. Сложить предложения, показать человеку как diff (T2). Цены/контакты контрагентов — T3.
5. После апрува/таймаута — git commit, обновить `updated` в `index.md`.

## Выход / формат
Список предложенных diff'ов + обновлённый `index.md`. Никаких тихих перезаписей.

## Правила и edge-cases
- Не выдумывать новые факты. Нет источника — не менять, а спросить.
- Не трогать `ROLE.md` и `SKILL.md` — это не KB (другой цикл, self-improvement).

## Эскалация
Противоречие между двумя «надёжными» источниками → человеку с обоими вариантами.
