# SKILL — watch-receivables

**Когда:** регулярный обзор дебиторки (пн 09:00) или по запросу. **Тир:** T1 (только мониторинг + уведомление, ничего не меняет).

## Цель
Дать владельцу короткий сигнал по деньгам: сколько должны, кто концентрирует риск (OLMA), что просрочено.

## Вход
- Сводка дебиторки из БД (в контексте): total, byClient с %, olmaPct, overdueCount/Amount,
  **агинг** (0–30/31–60/61–90/90+, не просрочено), **dueSoon** (к сроку ≤7 дней), **byMonth** (помесячно).
- `clients.md` (контекст по клиентам).

## Шаги
1. Прочитать сводку. Оценить **концентрацию OLMA**: ≥60% — 🔴 высокий риск, 40–59% — 🟡, <40% — 🟢.
2. Разобрать **агинг** (90+ — самое тревожное) и **кэш-сигнал** dueSoon — сколько денег к сроку ≤7 дней (ожидаемые поступления недели).
3. Дать 1–2 рекомендации (ускорить сбор по 90+, кандидаты на `draft-reminder`) — без выдумывания цифр.

## Выход / формат
```
💰 Дебиторка GLOBERENT — <дата>
Всего: <сумма> сум · 🌡 OLMA: <%> (<🔴/🟡/🟢>)
⚠ Просрочено: <N> на <сумма> — агинг: 0–30 <..> · 31–60 <..> · 61–90 <..> · 90+ <..>
💵 К сроку ≤7 дней: <сумма> (ожидаемые поступления недели)
Топ-должники: <клиент> <сумма> (<%>) · …
Рекомендация: <1–2 пункта; кандидаты на draft-reminder>
NEXT: draft-reminder по <должник>; уточнить срок по <позиция>
```
> Блок `NEXT:` (опц.) — follow-up подсказки: что разумно сделать дальше (через `;` или маркерами ниже). Платформа покажет их (F0.5).

## Правила (жёстко)
- Цифры — ТОЛЬКО из переданной сводки/БД. Нет данных → «нет данных по дебиторке», не выдумывать.
- Это мониторинг (T1): не создавать платежи/напоминания клиентам — для напоминания есть `draft-reminder` (T3).
- Краткость: сигнал, не отчёт на страницу.
