# Пакет направления

Скелет создаёт `scripts/new_direction.py`. Ниже — что должно быть в каждом файле и почему.

## Структура

```
ventures/<slug>/
├── DIRECTION.md        паспорт: оригинал, модель дохода, рынок, вердикт, KPI, kill-критерии, статус
├── clone-spec.md       что копируем 1:1 / адаптируем / убираем
├── agents/             один файл на агента (минимум operator и growth)
├── workflows/          cron и триггеры, Asia/Tashkent
├── skills/             навыки, специфичные для направления (SKILL.md в папке каждого)
├── launch/plan.md      чек-лист до первого дохода с датами
├── launch/product.md   лендинг / поток бота / подписка — как устроен продукт
├── launch/channels.md  каналы, креативы, бюджеты (T3)
└── reports/YYYY-WW.md  недельные отчёты Operator
```

## DIRECTION.md

- **Оригинал:** ссылка, что и как зарабатывает, доказательство дохода (H1)
- **Модель дохода клона:** кто платит, за что, сколько, как часто
- **Рынок:** профиль, ключевые адаптации
- **Вердикт и баллы:** из фазы 2
- **Гейт T3:** что одобрено владельцем (деньги, юрлицо, риск), дата
- **KPI:** дата первого дохода · доход/нед · CAC · маржа · часы владельца/нед (цель 0)
- **Kill-критерии:** переопределяют значения по умолчанию из SKILL.md
- **Статус:** scouted → approved → building → launched → earning → stopped
- **Ответственный агент:** operator

## clone-spec.md

Три колонки — «копируем», «адаптируем», «убираем» — с причиной в каждой строке двух последних. Цель — минимальное отклонение от оригинала: каждое изменение — гипотеза, которая может сломать доход.

## Шаблон агента (agents/<name>.md)

```markdown
# <slug>-<role>
**Задача (одна):** …
**Входы:** данные, файлы, события
**Выходы:** файлы, сообщения, действия
**Инструменты:** MCP / скрипты / API
**Автономия:** T0–T4 с перечнем T3-действий
**Триггеры:** cron / событие / сообщение
**Метрики:** что считает и куда пишет
**Эскалация:** при каких условиях и кому (обычно chief-of-staff, затем владелец)
**Регламент:** пошаговый порядок обычного запуска
```

Пиши по `PROTOCOL.md` репозитория, если он в контексте; этот шаблон — минимум, совместимый с ним.

## Workflow (workflows/<name>.yaml)

```yaml
name: <slug>-daily-ops
schedule: "0 9,15,21 * * *"   # Asia/Tashkent
agent: <slug>-operator
steps:
  - read: reports/latest
  - run: <действие>
  - if: <условие>
    escalate: T3
outputs: reports/YYYY-WW.md
```

## Навыки (skills/<name>/SKILL.md)

Создавай навык только для того, что повторяется внутри направления и отсутствует в общей библиотеке (например, генерация конкретного типа документа, разбор конкретного API). Формат — как у любого SKILL.md: name, description с триггерами, инструкции. Если навык пригодится другим направлениям — Curator переносит его в общую библиотеку.

## launch/plan.md

Чек-лист с датами до первого дохода. Обычный порядок: продукт готов → оплата принимается (тест на минимальную сумму) → оферта размещена → каналы запущены → первые 10 контактов → первый доход. У каждого пункта — ответственный агент. Пункты, требующие денег или подписи, помечены T3.

## reports/YYYY-WW.md

Доход · расходы (API, реклама, хостинг) · маржа · CAC · часы владельца · что изменил Operator · статус kill-критериев · одно предложение Curator'у.
