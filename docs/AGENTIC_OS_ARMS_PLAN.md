## 0. Резюме

В видео Agentic OS = **командный центр** (дашборд-домашняя страница с виджетами, skills deck,
доской рутин, кольцом артефактов и «вторым мозгом») поверх **ARMS** — Applications · Routines ·
Memory · Skills. По словам автора, интерфейс даёт 20–30 % ценности, остальные 70 % — организация
контекста и рабочего пространства под агента. Учить и строить — снизу вверх: Skills → Memory →
Routines → Applications, у каждого элемента три уровня зрелости.

MYDON по этой шкале:

| Элемент | Уровень MYDON сегодня | Что мешает подняться |
|---|---|---|
| Skills | ≈1,5 из 3 | 27 навыков объявлены в паспортах 12 агентов, исполняются 8 — навык в MYDON это TS-код, а не исполняемый markdown; «толстых» навыков с референсами нет; headless-запуск (эквивалент `claude -p` — Claude Agent SDK) есть, но только в помощнике |
| Memory | 1 из 3 | CLAUDE.md — частичный роутер; роутеров направлений нет; 51 ссылка из паспортов ведёт на отсутствующие файлы; «второго мозга» нет |
| Routines | **3 из 3 по архитектуре** | Свой сервер 24/7 с агентами и контекстом (то, что автор называет «скоро появится по умолчанию»); нет доски срабатываний, хуки цикла не формализованы |
| Applications | ≈2,5 из 3 | Свои коннекторы и микро-приложения есть; нет MCP-сервера над Core, навыка поиска коннекторов, панели здоровья интеграций |
| Командный центр | бизнес-слой закрыт | Нет skills deck, доски рутин, кольца артефактов, графа-мозга, живого статуса агентов |

Итоговая схема одна (§5): MYDON остаётся «одна оболочка — много движков», Core — единственный
источник фактов, а ARMS ложится сверху как дисциплина: навык = исполняемый markdown (тонкий или
толстый), память = роутер-файлы + Core, рутины = расписания + хуки с доской срабатываний,
приложения = коннекторы + MCP `mydon-core`, командный центр = переработанные `/mydon` и `/agents`
с виджетами из видео. **Venture Factory** (§7) — пятое направление `ventures` и первый
вертикальный потребитель всех четырёх слоёв: толстый навык, семь ролей-агентов, cron-разведка,
гейт T3, свои панели.

## 2. Что показано в видео

### 2.1 Командный центр автора

Домашняя страница, с которой он начинает день. На одном экране:

- сводка календаря (события, нужные часовые пояса);
- сводка почты, где Claude **пометил письма, требующие внимания**;
- быстрые ссылки на собственные микро-приложения;
- кастомные виджеты (у него — YouTube-метрики);
- **доска рутин**: какие запланированные задачи сработают и когда;
- **skills deck**: карточки навыков, которые имеет смысл запускать с дашборда; на карточке
  выбираются **уровень усилия и модель** для этого запуска, там же кнопка «запустить»;
- виджеты свободно меняют размер и место, новые создаёт Claude Code по запросу;
- **artifacts ring**: поиск всего, что Claude когда-либо сделал (по клиенту, по дате) с открытием
  HTML-файла;
- в центре — вход во **второй мозг**: визуализация файлов, навыков и связей рабочего пространства.

Тот же дашборд он продаёт клиентам как услугу (макеты для финансовой фирмы в Австралии, для
Beto Green): «если фундамент личной OS стоит, кастомизировать под клиента легко».

### 2.2 ARMS — четыре элемента, три уровня каждый

Аналогия автора: дать Claude «руки» — собственное рабочее пространство. Порядок обучения и
строительства — снизу вверх.

**Skills.** Правило: попросил одно и то же дважды — делай навык.
- *Уровень 1.* Готовые навыки Anthropic (Claude Desktop → Customize → Skills), в первую очередь
  `skill-creator`; вдохновение откуда угодно — пост в X про ускорение компьютера превращается в
  навык `/cleanup` одним промптом.
- *Уровень 2.* **Толстый навык**: не один `skill.md`, а папка, где `skill.md` — **роутер к
  референсам** (у автора `/robo` — дизайн-система: `brand.html` со шрифтами и палитрой, шаблоны,
  стили). Поэтому «Make a PDF guide with /robo …» даёт фирменный документ за 1–2 промпта.
  Есть промпт, который превращает тонкие навыки в толстые.
- *Уровень 3.* **Headless-запуск** — `claude -p "/cleanup"`: одноразовая сессия с заданной моделью
  и усилием, без чата; так навыки встраиваются в дашборды и внутренние приложения (skills deck
  в его командном центре), результат — отчёт-артефакт.

**Memory.** Чем больше пользуешься, тем больше файлов — память надо организовывать под агента.
- *Уровень 1.* Папка-workspace с файлами (у автора `Robo` — 60 000 файлов: медленный поиск,
  расход лимитов).
- *Уровень 2.* **Роутер-файлы.** Не раскладывать по папкам «для человека», а дать агенту карту:
  `claude.md` — главный роутер, описывает «отделы» и ссылается на тематические роутеры
  (`content.md`, …), каждый из которых — список навыков и референсов этого отдела. Агент читает
  файлы мгновенно — важна не навигабельность, а кратчайший путь.
- *Уровень 3.* **Визуальный второй мозг**: граф связей файлов, навыков и роутеров, быстрый поиск
  и предпросмотр — для объяснения системы другим и для себя.

**Routines.** Доверять агенту работу без присмотра можно только после навыков и памяти.
- *Уровень 1.* Рутины Claude Desktop (боковая панель Routines, естественный язык): рутина = промпт,
  который Claude посылает сам себе в заданное время («YouTube → Substack ежедневно в 8:00», на
  кастомном навыке → 70–80 % попадания в тон, артефакт ложится в OS). Ограничение: работает,
  **пока компьютер включён**.
- *Уровень 2.* Облако 24/7: агент на собственной машине в облаке (у автора Hermes; упомянуты
  OpenClaw и Grokbot), «доска срабатываний», а рабочее пространство с навыками и памятью
  синхронизируется с локальным через Syncthing.
- *Уровень 3.* **VPS с установленным Claude Code**: весь контекст живёт там, одна платформа, без
  синхронизации — автор ожидает, что это станет стандартом.

**Applications.** Реальная работа требует подключения приложений.
- *Уровень 1.* Коннекторы в Claude Desktop (Customize → Connectors).
- *Уровень 2.* Навык **`search connectors`**: Claude сам ищет официальный коннектор, а если его нет —
  сообществом сделанные **CLI / API / MCP** (три обычных формата), даёт рекомендацию; дальше —
  «проверь, безопасно ли, и настрой».
- *Уровень 3.* Свои коннекторы (CLI Printing Press — для сервисов без API: MyFitnessPal, Skool)
  и **свои приложения**: сам дашборд, лента генераций (masonry-сетка картинок и видео), второй
  мозг, «посадочная площадка» для Excalidraw-иллюстраций.

## 3. Дизайн

Из транскрипта: командный центр — **приложение из виджетов** (переставляемых и изменяемых по
размеру), с доской рутин, skills deck (усилие + модель + запуск), кольцом артефактов и графом-мозгом
в центре. Дизайн-система автора живёт как **толстый навык `/robo`** с `brand.html` (шрифты, палитра),
и все его артефакты — PDF, дашборд, курс, RUBRIC — сделаны через него, поэтому выглядят одинаково.

Визуальный язык этих публичных артефактов (курс, RUBRIC): почти чёрный холст (#111–#1a1a1a),
тёплый off-white текст, **оранжевый акцент #ff6b1a — тот же, что `--accent` MYDON**, моноширинные
метки с трекингом («BY THE NUMBERS»), геометрический гротеск в заголовках, пиксельный display-шрифт
для чисел и одного акцентного слова, пиксель-арт иконки и аватары, рамки с жёстким смещённым
контуром («стопка листов»), точечная сетка на фоне, переключатель темы. Тон — аркада/терминал,
«lean by design».

Для MYDON переносится **логика** (виджеты, deck, доска, кольцо, мозг, дизайн-система как навык)
и **грамматика** (метки, рамки, аватары, LED-статусы) на существующих токенах; пиксельные шрифты
для кириллицы не подходят (см. решение Р-2 от 22.08 о латинице) — §6.5.

## 5. Итоговая схема: MYDON = ARMS поверх Core

Неизменные принципы: одна оболочка — много движков; сначала реестр, потом дашборд; русский UI /
английский код; секреты только в `.env`; агент ничего не делает сам без тира; факты бизнеса — в
Core, знания и решения — в markdown.

```
                 ┌──────────────────────── Владелец ────────────────────────┐
                 │ Claude Code (harness)          CC — командный центр      │ Telegram-бот
                 │ .claude/skills (мета, дизайн)  виджеты · deck · доска    │ брифинг · гейты T3
                 │ CLAUDE.md → routers/*.md       кольцо · мозг · Ventures  │
                 └──────────────┬────────────────────────┬─────────────────┘
                                │ MCP `mydon-core`       │ REST
 ┌── A · Applications ──────────▼────────────────────────▼──────────────────────────────────┐
 │ apps/mcp (+) · packages/connectors · apps/bot · CLI `mydon` (+) · панель «Приложения» (+) │
 └───────────────────────────────────────┬──────────────────────────────────────────────────┘
 ┌── R · Routines ───────────────────────▼──────────────────────────────────────────────────┐
 │ schedule (cron по паспортам) · hooks pre/post-run (+) · outbox · watchdog · доска /crons (+)│
 └───────────────────────────────────────┬──────────────────────────────────────────────────┘
 ┌── M · Memory ─────────────────────────▼──────────────────────────────────────────────────┐
 │ CLAUDE.md = главный роутер · routers/{globerent,vendhub,personal,mydon,ventures,dev}.md (+)│
 │ apps/agents/shared/{COMPANY.md, kb/, PROTOCOL.md} (+) · docs/decisions · журнал памяти Core │
 │ панель «Мозг» /brain (+) — граф роутеров, навыков, агентов, документов                     │
 └───────────────────────────────────────┬──────────────────────────────────────────────────┘
 ┌── S · Skills ─────────────────────────▼──────────────────────────────────────────────────┐
 │ agents/<a>/skills/*.md — исполняемые: executor `code` | `llm` (+, Agent SDK = `claude -p`) │
 │ толстые навыки: SKILL.md-роутер + references/ + scripts/ · skills deck в CC (+)           │

                     Core (NestJS + Postgres) — единственный источник фактов
```

## 6. План внедрения — четыре волны по ARMS плюс дизайн

Порядок автора: снизу вверх. Каждая волна завершается проверяемым состоянием.

### 6.1 Волна S — навыки: исполняемый markdown, толстые навыки, deck

3. **Панель «Приложения»** (`/apps`): здоровье коннекторов (последний синк, ошибки) — мониторы уже

## 7. Venture Factory внутри ARMS

Навык `mydon-venture-factory` уже написан в форме **толстого навыка** уровня 2: `SKILL.md` — роутер к
`references/{scoring, sources, markets/*, direction-package, owner-profile}.md` и `scripts/`. Он
задаёт семь ролей с тирами, семифазный цикл с cron-разведкой, гейт владельца T3, kill-критерии,

Это делает фабрику идеальным **первым вертикальным потребителем** всех четырёх слоёв: она
нагружает каждый именно тем, что волны §6 и так строят.

### 7.2 Модель данных без новых таблиц

Направление = `project` (`orgId`, `name`, `status`) + `document` «DIRECTION.md» + агенты с
`business = 'ventures:<slug>'` (сейчас поле `business` — текст, менять схему не нужно) +
`money_flow` направления (доход и стоимость эксплуатации — основа kill-критериев) + `task` для
`launch/plan.md`. Кандидат = `entity('venture_candidate')`; clone-spec, отчёты, креативы —
`document`. Гейт — `approval`. Файлы `ventures/<slug>/` остаются **форматом авторства и сидом**
(тот же паттерн, что паспорты агентов: файл → сид → база — источник истины). `scripts/
new_direction.py` — переписать как `tools/new-direction.mjs` (в репо нет Python-тулчейна, все
инструменты — `.mjs`).

### 7.3 Режим product

Фабрика спроектирована так, чтобы работать для чужого владельца без правки кода — то же требование,
что и у MYDON («VHM24 сейчас один пользователь, пользователи появятся»). В Core уже есть `org` и
`orgId` у `project`/`entity`; web identity и owner-only RBAC заведены (enforcement выключен).
Значит: `owner-profile.md` → документ `org`, вкладка Ventures фильтруется по `orgId`, скоринг и
профили рынков — общие kb-страницы. Проверка на каждом шаге проектирования — вопрос из навыка:
«сработает ли это для чужого владельца без правки кода?»

### 7.4 Порядок запуска фабрики относительно волн

1. Интерактивный режим можно начинать **сразу после первой недели** (роутеры + `shared/`): навык
   кладётся в `.claude/skills/`, Scout/Analyst работают в Claude Code владельца, карточки и вердикты
   пишутся как `entity` через REST (импортёр `tools/import-ventures.mjs` по образцу `import-*.mjs`)
   до появления MCP.
2. Роли-агенты в AgentOS — вместе с волной S (`llm-skill`), начиная со Scout (T1, только чтение)
   и Analyst; Localizer/Builder — после `agents.create` в MCP (волна A); Launcher — последним,
   когда гейт T3 и коннектор оплаты проверены на одном направлении.
3. Вкладка `/domain/ventures` — минимальная (реестр + конвейер + гейт) в волне A, до Launcher:
   направление без Operator и kill-критериев не запускается — это правило самого навыка.

## 8. Что не переносить и риски

Не переносить: **Hermes / Syncthing / OpenClaw / Grokbot** — MYDON уже на уровне 3 по рутинам
(свой сервер, контекст на нём), а `openclaw` в denylist; **рутины Claude Desktop** — нет смысла при
сервере 24/7; **single-file zero-deps дашборд** как стек — ценность в панелях, не в отсутствии
зависимостей; **один Claude-сеанс на агента** (claudeclaw) — Core и ledger сильнее; **Obsidian /
файлы как хранилище бизнес-данных** — реестр в Postgres, markdown только для знаний и решений;
**пиксельные шрифты для текста**; **реестр фабрики в `seen.jsonl`** — в Core.

Риски: рост расхода LLM при оживлении 19 навыков и разведке 3 раза в день (ledger, `per_day_usd`,
включать по одному); соблазн поднять `AGENT_AUTONOMY_MAX` ради «автономии как в видео» (держать
T0/T1 до статистики coach-review; у фабрики T3 на деньги — всегда); prompt-injection через источники
Scout (`untrusted.ts`, вердикт только с доказательством, никаких покупок и публикаций без T3);
двойной источник правды файлы vs Core (правило: факты — Core, знания — markdown, файлы — сид);
перегрузка первой волны (S до конца, потом M; фабрика — интерактивно, пока слои не готовы).

## 10. VendHub: сменные узлы, инвентаризация, возврат бункеров, товары на складе (план 04.09, вечер)

инвентарный номер и статус (в автомате · мойка · ремонт · склад); карточки на весь парк (4 миксера + гриндер +
варка + бункеры на аппарат) система заводит сама **без номера**, номер проставляется постепенно по напоминанию;
инвентаризация узлов — по одному, с фото и серийником; возвращённые бункеры взвешиваются и приходуются;
в остатках склада нужны товары на перепродажу, не только ингредиенты.
