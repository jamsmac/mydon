# План поглощения mydon-stock → mydon

Дата: 2026-08-24. Решение владельца: **mydon не должен быть связан с
mydon-stock ничем** — stock остаётся только донором готовых решений, все
функции живут в самом mydon. План построен на полной инвентаризации обеих
кодовых баз и трассировке связей (workflow wf_fe36fe5d, 4 агента, всё с
file:line).

Ключевой принцип порядка: **сначала снимаются зависимости mydon ОТ stock,
потом гасятся пользовательские контуры stock** — каждый только после
появления полноценной замены. Методика владельца действует: считать всё,
что уже можно; чего нельзя — держать в книге «Пробелы», не молчать.

## 0. Инвентарь живых связей (что предстоит разорвать)

| # | Связь | Где |
|---|---|---|
| 1 | Учётный поток: core читает БД stock read-only — `ourvend_sales`→`sale`, `purchases`→`purchase`, `ourvend_machine_stock`→`machine_stock`, `machines`→карточки | `sales.service.ts:116`, `supply.service.ts:188`; выключатель `STOCK_DATABASE_URL` |
| 2 | Docker-сеть `mydon-stock_default` (транспорт для №1, создаётся compose-проектом stock) | `deploy/docker-compose.yml:215` |
| 3 | Оффсайт-бэкап БД **mydon** уходит через Telegram-бота **stock** (`BOT_TOKEN`/`TG_BACKUP_CHAT_ID` из `/opt/mydon-stock/.env`) | `deploy/guards/backup_extra.sh:114,208` |
| 4 | Guards-скрипты mydon (backup_offsite/healthz_guard/disk_guard) исполняются по cron **из /opt/mydon-stock** | `deploy/guards/*`, cron хоста |
| 5 | Словарь серийников: stock — источник формы `c…`, mydon — единственное место сопоставления | `packages/shared/src/machine-serial.ts` |

Приложение stock само в mydon не ходит вообще; обратных вызовов нет.

## Срезы

### П1. Опс-развязка бэкап-канала (мал, без риска)
`backup_extra.sh` переводится с бота склада на аварийного бота сторожа
(`WATCHDOG_BOT_TOKEN`/`WATCHDOG_CHAT_IDS` из `/etc/mydon-heartbeat.env`) —
прецедент уже создан в `auto-deploy.sh` (PR #201). Доставка — по `"ok":true`.
Закрывает связь №3. После этого падение/переезд stock не ломает бэкапы mydon.

### П2. Учётный поток OurVend — свой (самый важный срез)
Пока он не сделан, **stock выключать нельзя вообще** — mydon ослепнет по
продажам и приходу.

Перенести в mydon (донор: `app/ourvend.py`):
- суточный снапшот продаж по автоматам и дням (`snapshot_days`) с догоном
  пропусков до 14 дней и идемпотентной перезаписью дня (DELETE+INSERT в
  транзакции);
- утренний снимок остатков слотов (`snapshot_machine_stock`, пагинация Lot
  management, фильтр чужих MId);
- **НОД-дедуп** повторяющихся строк ответа (×1/×2/×3 — тест уже есть у
  донора);
- отказ при >500 строк вместо тихой обрезки; логин без ретраев (риск
  блокировки аккаунта os.ourvend.com).

Писать напрямую в свои `sale` / `machine_stock` тем же каноном серийников
(`machineSerialKeys`). Разместить в `apps/agents` рядом с существующим
синком слотов; у систем сейчас РАЗНЫЕ учётки OurVend — на переходный период
двойного съёма следить за блокировками, целевое состояние — один коннектор,
два потока (учётный суточный + плановый 3-часовой).

Критерий готовности: 7 подряд дней самостоятельного съёма сходятся со
съёмом stock до строки. После этого `STOCK_DATABASE_URL` пустеет, сеть
`mydon-stock_default` снимается из compose (связи №1 и №2 закрыты).

### П3. Закупки — донести бот-мастер до уровня донора
Каркас в mydon уже сильнее (заявка→approval→накладная→приёмка с
распределением в автоматы). Донести из FSM-мастера stock:
- **price gate**: подтверждение при отклонении цены >20% от последней;
- фото чека с форвардом в архив (у `stock_batch` уже есть `source=receipt`);
- срок годности позиции при приёмке (для вендинг-товаров);
- мультипозиционная сессия и подсказки последней цены/количества.
Затем гасится синк `purchases` (часть связи №1) и ручные формы панели stock.

### П4. Полевой снек-контур в боте
- включить и доделать мастер «Заполнил автомат» (`staff-refill.ts`,
  сейчас ready:false; Core API `POST /vending/refills` уже есть);
- инвентаризация автомата задним числом (выбор часа, `counted_at`);
- перемещения между складами в боте (тип `transfer` в ленте уже есть);
- **3-сторонняя усушка** автомата (ожидаемо−факт в сумах по avg_cost,
  алерт ≥30 000 сум) — донор `reports.py:345`.
Затем гасится синк `ourvend_machine_stock` (снимки к этому моменту свои).

### П5. Аналитика и отчёты
Донести из `reports.py`: «что купить» с поставщиками/бюджетом (426–528),
`dead_stock` 21 день (591), `price_changes` >5% (622) и динамика цен,
**маржа по автоматам** (567 — заодно закрывает заглушку «Себестоимость»
в CC), недельная сводка + подписки на рассылки, живая сверка OurVend из
бота + `price_gap_report` (витрина против sale_price).

### П6. Данные и справочники
- **Фискальный блок товаров**: ИКПУ, МХИК (17 цифр), НДС, штрихкод EAN,
  код упаковки, маркировка, name_uz + валидация + системные словари.
  Нужен для фискализации — переносится карточкой товара CC;
- журналы `audit_log` (before/after JSONB) и `deletions_log` — у карточек
  и операций mydon; «Мои записи» в боте (15 последних, удаление с логом,
  лимит 24 ч не-админу);
- EAV-конструктор полей — ТОЛЬКО если реальная потребность останется
  после фискального блока (не тащить по инерции);
- гранулярные права/подписки — по потребности, поверх `person.roles`.

### П7. Задачи — отдельное решение владельца
В монорепо модуля задач нет. Варианты: перенести лёгкие tasks донора
(open/done/confirmed + TG-уведомления + подтверждение менеджером) или
закрыть потребность существующими approvals/событиями/дайджестами.
Рекомендация: переносить как маленький модуль в срезе П7, когда полевой
контур (П4) начнёт порождать реальные задачи.

### П8. Финал — вывод stock
1. Миграция истории: `purchases`, `stock_counts`, `refills`, ручные
   `sales`, `ourvend_sales` (учесть `OURVEND_EPOCH=2026-01-01` и
   намеренные дубли `archive/`);
2. переселение guards-скриптов и бэкапа склада с путей `/opt/mydon-stock`
   на пути mydon (cron хоста!);
3. вывод панели :8080 и бота @mydonvendbot;
4. заморозка БД stock как архива (volume не удалять — правило отката);
5. чистка: `STOCK_DATABASE_URL`, `external`-сеть, упоминания в докладах
   `/gaps`, `docs/DATA_SOURCES.md §891` (канон продаж — на свой снапшот).
