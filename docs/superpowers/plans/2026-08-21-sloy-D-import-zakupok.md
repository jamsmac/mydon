# Срез D: импорт истории закупок — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** поднять историю закупок сырья за год из Excel-реестра владельца в партии,
чтобы по каждому ингредиенту было видно, когда и почём его брали, а не только
последнюю цену.

**Architecture:** реестр разбирается чистой функцией в `packages/shared`, ядро
принимает пачку строк и заводит партии идемпотентно, имена источника связываются
с карточками через предложение + подтверждение владельца. Историческая партия
закрывается расходом того же объёма — иначе прошлогодние приходы задвоили бы
сегодняшний остаток.

**Tech Stack:** собственный разбор xlsx (`packages/shared/src/xlsx.ts`, без
зависимостей), NestJS (apps/core), Next.js App Router (apps/cc), `node --test`.

**Spec:** `docs/PLAN_UCHET_SYRYA.md` §5 Срез D. Разбор данных, на котором стоит
план: `/Users/js/.claude/jobs/6ffc322e/tmp/register-analysis.md`.

## Ruling'и

- **R-D1. Историческая партия закрывается расходом.** Каждая импортированная
  партия получает приход И равный расход, датированный днём инвентаризации
  владельца, с пометкой «израсходовано до инвентаризации 21.08.2026, точная дата
  неизвестна». Иначе прошлогодние приходы задвоят сегодняшний остаток: у кофе
  стало бы ~293 кг вместо 43 (факт 10). Что это даёт: баланс не меняется, остаток
  партии ноль (значит она не всплывёт на экране сроков), история цен и документов
  сохранена. Цена ошибки: в ленте склада появятся парные движения — они честно
  подписаны и удаляются вместе с партией.
- **R-D2. Срез D берёт только строки, ложащиеся на карточки сырья.** Снек-товары,
  вода и сиропы попадают в отчёт «не импортировано» с причиной. Расширять партии
  на `type=product` в этом срезе НЕ будем: у снека свой контур (`vending_stock`
  считает штуки по названию), и правка `cardOfType` потянула бы за собой
  `baseUnitOf`/`packageWeightSnapshot`, написанные под ингредиенты (факт 8).
  Цена ошибки: часть реестра останется историей только в отчёте, а не в партиях.
- **R-D3. Дата прихода — из текста счёта-фактуры.** Не нашлась — берём дату
  оплаты, но ТОЛЬКО правдоподобную (не в будущем). Нет и её — строка НЕ
  импортируется, а попадает в отчёт «нужна дата». Выдуманная дата хуже
  отсутствующей: она сдвинет и срок годности, и порядок FEFO. Цена ошибки:
  47 строк (28,1 млн) ждут, пока владелец поправит таблицу.
- **R-D4. Предложение ≠ привязка.** Импортёр ПРЕДЛАГАЕТ карточку с обоснованием
  («поставщик KMS ROASTING TRADING, у него в реестре одно наименование» /
  «в имени есть слово „шоколад“»), но связь создаётся только подтверждением
  владельца. Нечёткого сравнения не вводим — тот же запрет, что в срезе B:
  молча связать «Чай VENESSA VL 2.5 Lemon» не с тем чаем значит увести историю
  закупок на чужую карточку. Исключение — точное совпадение нормализованных
  имён (сегодня таких 0). Цена ошибки: владельцу подтвердить ~10 имён вместо 59.
- **R-D5. Идемпотентность — по `(source, extId)`.** `extId` строится
  детерминированно из реестра: `«счёт-фактура»::«наименование»::«номер строки
  файла»`. Повтор загрузки обязан быть мягким пропуском, а не ошибкой Postgres
  (факт 9). Цена ошибки: прерванный прогон дозагружается без дублей.
- **R-D6. Загрузка идёт через уже существующий разбор xlsx** (факт 11), а не
  через новую зависимость. Цена ошибки: если `parseXlsx` не потянет этот файл,
  задача эскалируется, а не тащит библиотеку.
- **R-D7. Сначала предпросмотр, потом запись.** У импорта обязателен режим
  «показать, что будет» — сколько строк, на какие карточки, сколько без даты,
  сколько не сопоставлено. Запись — отдельным подтверждённым действием.

## Global Constraints

- TypeScript strict, без `any`. UI по-русски, код по-английски.
- `pnpm -s build` (11/11), `pnpm -s test` (21/21), `pnpm -s --filter cc lint` — 0.
  Тесты бота гоняются по `dist` → перед ними `pnpm --filter bot build`.
- Часовой пояс Asia/Tashkent; даты — `date` (YYYY-MM-DD).
- Количества дробные: `numeric`, никаких `parseInt`/`Math.trunc` на количествах.
- Деньги — с НДС там, где так в реестре; цена без НДС считается только если
  известна ставка. Отрицательная цена — опечатка, не цена.
- Прод-БД: чтение свободно, запись — только через подтверждённый импорт, который
  запускает контроллер (не субагент).
- Миграции применяются автодеплоем БЕЗ отката.
