# Срез F: норма против факта по сырью — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** показать, сколько сырья ДОЛЖНО было уйти по рецептам против того,
сколько реально залито, — и при этом ни разу не обвинить в недостаче там, где
просто не вели записи.

**Architecture:** норма считается из живых продаж (`coffee_order` × состав
карточки × размещение автомата); факт — из пар «заливка → возврат» бункера;
единица сравнения — ПЕРИОД БУНКЕРА, а не месяц; вердикт выдаётся только при
полном покрытии периода записями, иначе строка честно говорит «нет данных».

**Tech Stack:** Drizzle + Postgres, NestJS, Next.js App Router, `node --test`.

**Spec:** разведка 22.08.2026 (workflow `scout-sloy-f`, 4 направления + синтез),
результаты вклеены ниже как проверенные факты.

## Ruling'и

- **R-F1. Единица сравнения — ПЕРИОД БУНКЕРА, а не месяц и не точка.**
  Пара «заливка → возврат» — единственное место, где обе стороны меряют одно и
  то же на одном интервале. Цена ошибки: строк больше, чем при помесячном
  разрезе; зато разница означает расход, а не смещение границ.
- **R-F2. Вердикт зависит от ПОКРЫТИЯ, а не только от дельты.** Строка
  получает `ok`/`расхождение` только если период закрыт целиком: есть парная
  заливка И возврат, позиция однозначна, тара откалибрована, размещение
  автомата есть, норма за интервал считается. Иначе — `нет данных`, отдельным
  счётчиком. **Это главный рулинг среза** (см. факт 4: сегодня порог 10%
  обвинил бы КАЖДУЮ точку в недостаче 30–56%).
- **R-F3. Порог и сигналы — НЕ в этот срез.** Включать оповещения можно только
  после того, как на 2–3 контрольных точках факт сошёлся с нормой хотя бы на
  одном полном цикле бункера. Сигнал, который врёт с первого дня, отучает на
  себя смотреть. Цена ошибки: владелец подождёт с алертами.
- **R-F4. Старый контур сверки (факт 6) не наполняем, а помечаем мёртвым.**
  Две пустые таблицы и 112 строк «неизвестно» — это третий механизм рядом с
  новым. Убрать из навигации в этом срезе, удалять код — отдельным решением.
- **R-F5. Расход считается по `orderIsDelivered`, не по `countable`**
  (факт 12): сырьё тратится на ВЫДАННЫЙ напиток, а не на оплаченный.
  Расхождение 3 042 чашки обязано быть видно числом, а не растворяться.
- **R-F6. Алиасы имён для кофе — переиспользуем снековый механизм**
  (`product_name_alias` + `sales.service.ts:459`), не пишем второй.
- **R-F7. Ввод данных — задача владельца, и она НЕ блокирует срез.** Считаем
  то, что считается; чего нет — показываем реестром пробелов (срез К уже даёт
  механизм). Пробелы факта 7–10, 13, 14 заводим строками в `/gaps`.

### Task 1: Норма из живых продаж

**Interfaces:**
```ts
/** Строка состава карточки: сколько ингредиента на одну порцию. */
export interface RecipeLine { ingredient: string; qty: number; unit: string }
/** Разбор `entity.attrs['состав']` в строки. Мусор — не молча ноль, а ошибка. */
export function parseRecipe(raw: unknown): RecipeLine[] | { error: string };
/** Норма на N порций: граммы (или штуки) по каждому ингредиенту. */
export function normFor(lines: RecipeLine[], cups: number): Map<string, { qty: number; unit: string }>;
```

- [ ] **Шаг 1: тест сначала.** Значения — с живых карточек:

```ts
it("состав переводится в норму на партию чашек", () => {
  const r = parseRecipe([{ ingredient: "Кофе", qty: 8, unit: "г" }]) as RecipeLine[];
  const n = normFor(r, 100);
  assert.deepEqual(n.get("Кофе"), { qty: 800, unit: "г" });
});

it("штуки не превращаются в граммы", () => {
  // Стакан считается в штуках. Зашитая «г» теряла крупнейшую статью (факт 11).
  const n = normFor([{ ingredient: "Стакан", qty: 1, unit: "шт" }], 25252);
  assert.deepEqual(n.get("Стакан"), { qty: 25252, unit: "шт" });
});

it("пустой состав — не норма ноль, а признак отсутствия рецепта", () => {
  const r = parseRecipe(null);
  assert.ok("error" in r, "нет состава — это «не знаем», а не «ноль граммов»");
});

it("отрицательное количество в составе — ошибка ввода", () => {
  assert.ok("error" in parseRecipe([{ ingredient: "Кофе", qty: -8, unit: "г" }]));
});
```

```ts
export type Полнота = "полный" | "нет возврата" | "нет заливки" | "позиция неоднозначна"
  | "тара не откалибрована" | "нет размещения" | "нормы нет";
export interface ПериодБункера {
  machineId: string; position: number; ingredientId: string | null;
  from: string; to: string;
  залито: number; возвращено: number; факт: number;
  норма: number | null; чашек: number;
  полнота: Полнота;
  /** Разница считается ТОЛЬКО при полноте «полный». Иначе null. */
  разница: number | null;
}
```

- [ ] **Шаг 1: тест сначала** — на числах разведки:

```ts
it("возврат тяжелее заливки — не отрицательный расход, а «тара не откалибрована»", () => {
  // 282 пары из 885 такие (факт 5). Молчаливый минус тут дал бы отрицательный
  // расход и «перерасход» с обратным знаком на витрине.
  const p = периодБункера({ залито: 500, возвращено: 700, норма: 400, чашек: 50 });
  assert.equal(p.полнота, "тара не откалибрована");
  assert.equal(p.разница, null, "разницы нет там, где вход противоречив");
});

it("нет нормы за интервал — «нормы нет», а не недостача 100%", () => {
  const p = периодБункера({ залито: 500, возвращено: 100, норма: null, чашек: 0 });
  assert.equal(p.полнота, "нормы нет");
  assert.equal(p.разница, null);
});

it("полный период считает разницу", () => {
  const p = периодБункера({ залито: 780, возвращено: 250, норма: 500, чашек: 62 });
  assert.equal(p.полнота, "полный");
  assert.equal(p.факт, 530);
  assert.equal(p.разница, 30);
});
```
