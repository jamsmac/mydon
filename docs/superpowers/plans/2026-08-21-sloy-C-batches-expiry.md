# Срез C: партии и сроки годности — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** завести партию как единицу учёта сырья и товара (что, откуда, почём,
до какого числа), показать сроки годности на экране вместо заглушки и дать
партии реальный путь ввода — чтобы «когда это привезли и когда испортится»
перестало быть знанием в голове оператора.

**Architecture:** `stock_batch` по `docs/WAREHOUSE_SPEC.md` §4.3 плюс цена и
документ прихода (решение Р3/Р4 плана учёта сырья). Остаток партии — леджером
(сумма движений с этим `batch_id`), а не денормализованным полем: так уже
устроен `stock_movement`, и так не бывает рассинхрона. `batch_id` в движении
nullable — приход без партии остаётся законным, иначе сломался бы существующий
синк снабжения, у которого партий нет вовсе.

**Tech Stack:** Drizzle + Postgres (packages/db), NestJS (apps/core), Next.js App
Router server components (apps/cc), чистый TS + `node --test` (packages/shared).

**Spec:** `docs/PLAN_UCHET_SYRYA.md` §4 (Р3, Р4, Р5), §5 Срез C;
`docs/WAREHOUSE_SPEC.md` §4.3 (поля и инварианты — дословно ниже).
Отклонения перечислены в «Ruling'ах», каждое с причиной и ценой ошибки.

## Ruling'и

- **R-C1. Трассировка партии до бункера — двойным join, без новых колонок.**
  `coffee_refill → coffee_ingredient.entity_id → stock_batch.ingredient_id`.
  Текст плана учёта сырья обещал `ingredient_entity_id` в трёх таблицах, но срез B
  сознательно сделал узкий мост. Дублировать связь — завести рассинхрон.
  Цена ошибки: join на один переход длиннее; данные не расходятся.
- **R-C2. FEFO переносим, но к списанию НЕ подключаем.** `WAREHOUSE_SPEC` §1.3
  прямо называет FIFO-списание несделанным; Р3/Р4 пересматривают только
  *аналитическую* себестоимость. В этом срезе `allocateFEFO` работает на ЧТЕНИЕ:
  экран сроков показывает, какая партия уйдёт следующей. Автосписание меняет смысл
  существующих движений — это отдельный срез. Цена ошибки: остаток по-прежнему
  считается по ингредиенту целиком, партия отвечает «что испортится», а не
  «что списалось».
- **R-C3. `fefo.ts` переносится с двумя правками, и это не переписывание:**
  `batchId: number → string` (у нас uuid) и снятие `Math.trunc` (сырьё дробное:
  1,5 кг матчи, 10 600 г MacCoffee). Донорские тесты переносятся все семь и
  дополняются дробным случаем. Цена ошибки: без правки партия матчи усохла бы
  до 1 кг молча.
- **R-C4. `stock_batch.supplier_id` — настоящий FK на `entity(id)`,** а не имя
  строкой. У партии из Didox есть ИНН, значит контрагент однозначен;
  `matchContractorByName` зовём один раз при заведении, дальше держим ссылку.
  Хрупкое сопоставление по имени в карточке ингредиента остаётся как есть —
  это не наш срез. Цена ошибки: партия без распознанного поставщика хранит null
  и видна на экране как «поставщик не распознан».
- **R-C5. Цена партии хранится в трёх видах: без НДС, ставка, с НДС.** Документ
  даёт цену без НДС и ставку, а вся система считает в ценах с НДС. Хранить одно
  и пересчитывать на чтении — значит спорить с документом на округлениях.
  Цена ошибки: три поля вместо одного; расхождение с документом видно сразу.
- **R-C6. Ввод партии — форма прихода в `StockPanel`.** Минимальный реальный путь
  (бот не трогаем: у него нет места под номер счёта-фактуры, а оператор его не
  знает). Массовый импорт из Didox/Excel — срез D сразу следом. Цена ошибки:
  до среза D партии заводятся руками, но заводятся.
- **R-C7. Миграция 0060 повторяет защитный паттерн 0059** дословно: `IF NOT
  EXISTS`, `DO $$ … EXCEPTION WHEN duplicate_object`, только частичные уникальные
  индексы, никаких `NOT NULL` без дефолта на существующих строках. Перед
  написанием — `db:generate` и проверка, что дрейфа нет (в срезе B дрейф был и
  чуть не повесил автодеплой).
- **R-C8. Заглушка «Сроки годности» перестаёт быть заглушкой, а дефолт «Отчётов»
  чинится явным указанием.** Порядок листьев не должен решать, куда приземляется
  человек.
