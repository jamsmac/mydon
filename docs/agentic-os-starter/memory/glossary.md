# Глоссарий MYDON

| Термин | Значение |
|---|---|
| **Core** | `apps/core` — NestJS API + Postgres: реестр, события, согласования, задачи, ledger LLM. Единственный источник фактов. |
| **CC / оболочка** | `apps/cc` — веб-панель Next.js: Command Center + рабочие места направлений. |
| **AgentOS / Agents** | `apps/agents` — рантайм агентов: паспорта, навыки, cron, политика T0–T4. |
| **Паспорт агента** | `agents/<name>/config.yaml` + `ROLE.md`; сид в таблицу `agent`, после сида база — истина. |
| **Навык (skill)** | `agents/<name>/skills/<skill>.md` с frontmatter (`name`, `description`, `allowed-tools`, `requires-approval`); исполнитель — код (`skills.ts`) или LLM (`executor: llm`, план). |
| **Толстый навык** | Папка навыка: `SKILL.md`-роутер + `references/` + `scripts/` (термин из видео RoboNuggets). |
| **Роутер** | Markdown-файл-карта: куда смотреть по направлению (`routers/*.md`), главный — `CLAUDE.md`. |
| **Тир (T0–T4)** | Уровень самостоятельности: T0 только спрашивает · T1 предлагает, решает владелец · T2 мелкое сам · T3 многое сам · T4 почти всё сам. Действие исполняется без согласования, только если его тир ≤ порога. |
| **Floor (пол тира)** | Минимальный тир действия из нескольких источников (карточка агента, frontmatter навыка, тип инструмента) — строже побеждает. |
| **HITL** | Human-in-the-loop — согласование владельца во Входящих и в Telegram. |
| **Break-glass** | Навыки/операции, которые всегда идут через согласование и аудит, независимо от порога. |
| **Approval / согласование** | Запись `approval` в Core: предложение агента, ждущее решения владельца. |
| **Proposal / предложение** | Результат навыка: `action` (что и почему) + `facts` (на чём построено) + `next`; без повода — `null`, согласование не создаётся. |
| **Дельта-память** | Агент повторяет подачу только если изменилась сигнатура фактов (`memory.ts`); `no-signal` — повод исчез. |
| **Ledger LLM** | Денежный учёт вызовов моделей: reserve → settle, потолки `LLM_GLOBAL_DAILY_BUDGET_USD`, `per_day_usd`; fail-closed. |
| **Брифинг** | Утренняя сводка владельцу 07:30 в Telegram (4 тревоги) — то же на `/mydon`. |
| **Входящие** | `/inbox` — решения агентов + карточки реестра на утверждение (один вход). |
| **Карточка 360** | Экран объекта реестра со всеми связями (`/card/[id]`). |
| **Направление (домен)** | GLOBERENT · VendHub · Личный контур · MYDON · Ventures (план) — `DOMAINS` в `packages/shared`. |
| **Ventures / фабрика направлений** | Система агентов, которая находит, клонирует и запускает автономные бизнесы как направления MYDON (`routers/ventures.md`). |
| **GO / PARK / NO** | Вердикты фабрики по кандидату: запускать · отложить с условием · отказ с причиной в реестр. |
| **H1–H5** | Пять жёстких проверок скоринга фабрики; один провал = NO. |
| **Kill-критерии** | Условия остановки направления (45 дней без дохода, 3 недели убытка, >1 часа владельца в неделю, оригинал умер). |
| **Донор** | Существующий проект, откуда переносится готовый код (VendHub-OS, VHM24, mydon_1, mydon-agent-os, PROMACH). |
| **SDD / superpowers** | Процесс спека → план в `docs/superpowers/`. |
| **Hookify** | Правила-хуки Claude Code в `.claude/hookify.*.local.md` (блок пуша в main). |
| **OurVend / VHM24 / gjvending / VendingHub** | Источники телеметрии и продаж автоматов; VHM24 — собственный движок VendHub. |
| **Didox** | ЭДО/электронные счета-фактуры (коннектор GLOBERENT). |
| **OLMA** | Ключевой клиент GLOBERENT с высокой концентрацией дебиторки (приоритет `mydon-finance`). |
| **MYDON/OS** | Headless-сервер на Hetzner с браузерным доступом к Claude Code и инструментам (Tailscale). |
