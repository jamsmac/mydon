# СПЕКА: контрагент → место → автомат

Записано со слов владельца 10.09.2026. **Код не начат.**

## 1. Слова владельца

> Автомат ставится по договору с организацией — в чужих местах. Значит должен
> быть контрагент: например, центр кардиологии — наш контрагент, и уже у него
> ставим точки, а наименование места будет «первый корпус», «второй корпус»,
> «четвёртый корпус». Так же с KIUT.
>
> Каждый аппарат имеет свой серийный номер, а также порядковый номер с
> буквенной отметкой типа аппарата — от нашего предприятия.
>
> При создании автомата нужна возможность и ввода координат вручную, и отметки
> места на карте; при отметке система сама определяет координаты и адрес.

## 2. Что уже есть на проде (проверено 10.09.2026)

Реестр VendHub, 213 карточек: контрагенты **7**, точки (`location`) **30**,
склады (`warehouse`) 3, автоматы **31**, товары / ингредиенты 71 / 9.

- **Контрагенты уже заведены** — семь карточек. Ставить с нуля не нужно.
- **Карта-пикер уже написан.** В форме «Новое место» есть два поля координат
  руками и карта: клик ставит точку с точностью до шести знаков
  (`apps/cc/src/components/map-picker.tsx`).
- **Адрес по клику НЕ определяется.** Поле «Адрес» — свободный текст;
  обратного геокодирования нет.
- **Связи «место → контрагент» нет вообще.** Ни колонки, ни поля в карточке.
- **Номера от предприятия у автоматов нет.** Есть серийник
  (`entity.external_ref`, нормализация в `machine-serial.ts`) и вид
  (`machine_card.kind`: coffee/snack/drink/combo/other).

## 3. Находка: координаты лежат не на том объекте

Панель сохраняет координаты и адрес **на карточку автомата**
(`saveLocation(machineId, …)` в `apps/cc/src/app/card/actions.ts`), и карта
парка рисует именно автоматы (`live-map.tsx`, `machinePoints`).

Это неверно по сути. Координата описывает **место**: место стоит на земле и не
двигается, аппарат переезжает. Последствия видны сейчас:

- при каждом переезде автомата координаты надо вводить заново;
- у мест координат нет — **8 карточек мест из 33** пустые, хотя адреса известны;
- увезли автомат на склад — точка исчезла с карты, хотя она никуда не делась.

## 4. Правила

- **М-1. Три уровня.** Контрагент → место (корпус, этаж, холл) → автомат
  (железо, которое там стоит сейчас). Уровень «автомат ↔ место» уже есть —
  `machine_placement` с открытым периодом. Не хватает верхнего.
- **М-2. Место принадлежит контрагенту.** У карточки места ссылка на
  контрагента — необязательная по схеме. Предлагается тонкая таблица
  `place_card(entity_id, contractor_id, …)`, а не поле в `attrs`: ссылку надо
  соединять запросом. Вид места остаётся `entity.type`, его не трогаем (причина
  расписана в `packages/shared/src/place-kinds.ts`).
- **М-3. Название места — короткое, в пределах контрагента.** «4 корпус», а не
  «4 корпус кардиология». Полное имя собирается на показ: «Центр кардиологии ·
  4 корпус».
- **М-4. Координаты переезжают на место.** Карта парка рисует места, автоматы
  показываются на них. Форма координат у карточки места — та же, что при
  создании: два поля плюс карта.
- **М-5. Клик по карте определяет адрес.** Обратное геокодирование, адрес
  подставляется и остаётся правимым. Автоподстановку помечаем источником — она
  не факт со слов человека (R-H-8).
- **М-6. У автомата два номера, и они разные по смыслу.** Серийник — заводской,
  чужой, по нему сходится выгрузка Ourvend. Инвентарный — наш, с буквой вида.
- **М-6a. Приём уже написан — для узлов.** В `packages/shared/src/parts.ts` есть
  серии по виду (`B` варочная группа, `G` кофемолка, `M` миксер, `H` бункер,
  `F` фильтр), `normalizeInventoryNo`, `INVENTORY_NO_PATTERN`,
  `formatInventoryNo`, `suggestInventoryNo` и уникальный индекс. Для автоматов
  это тот же код с другим словарём серий, а не новая разработка.
- **М-7. Автомат перестаёт называться по месту.** Сейчас карточки зовутся «Olma
  Администрация», «KIUT Библиотека» — именем точки. Переезд ломает имя, а два
  написания одной точки дают две карточки.
- **М-8. Серии автоматов — K / S / D / C** (решение агента 10.09.2026 по
  поручению «прими решение»). `K-001` кофейный, `S-001` снек, `D-001` напитки,
  `C-001` комбо; вид «прочее» номера не получает. Три знака, нумерация ПО ВИДУ.
  **Почему одна латинская буква:** ровно как у узлов (B, G, M, H, F), и ни одна
  из K/S/D/C с ними не сталкивается.
  **Известный риск:** латинские K и C выглядят как кириллические К и С. Если
  техник наберёт кириллицу, `INVENTORY_NO_PATTERN` (только A–Z и цифры)
  отвергнет ввод с ошибкой, а не примет молча. Громкий отказ дешевле нечитаемой
  буквы на наклейке.
- **М-9. Двойные названия точек сливаются** (владелец 10.09.2026) — после
  полевой проверки. **Слияние — не переименование.** Заливки, узлы, размещения
  и задачи висят на РАЗНЫХ карточках: у «кардиология 4 корпус» семь заливок, у
  «4 корпус кардиология» — все узлы. Нужна отдельная операция «слить карточки»:
  перенести все ссылки на одну, вторую закрыть с пометкой «слита в …», всё одной
  записью в журнале. Переименование потеряет половину истории.
- **М-10. Адрес — не ключ. Координаты у места, всегда** (владелец 10.09.2026).
  У одного контрагента бывает несколько мест по ОДНОМУ адресу, но с РАЗНЫМИ
  координатами: у KIUT это библиотека, общежитие, клиника и M corp.
  Три следствия:
  1. Координаты задаются у КАЖДОГО места отдельно. Наследовать от контрагента
     нельзя.
  2. Имя места уникально В ПРЕДЕЛАХ контрагента, а не глобально.
  3. **Слияние по совпадению адреса ЗАПРЕЩЕНО.** Прямое ограничение М-9:
     сливать можно только по подтверждённому совпадению самого места — серийник
     автомата, полевая проверка. Наивное «один адрес — одно место» схлопнуло бы
     четыре корпуса KIUT в один.
  На карте такие места дают точки рядом друг с другом. Это правильная картина, а
  не дубликат, и очередь «проверить дубликаты» не должна их подсвечивать.
- **М-11. У наших собственных мест контрагент — наша компания** (владелец
  10.09.2026: «можешь поставить нас самих, GLOBERENT FINANCE офис»). Склад и
  мастерская получают ссылку на карточку собственной компании
  (`entity type=own_company`). Ссылка остаётся необязательной по схеме, но пустой
  не оставляем: «наше» — это ответ, а пусто должно значить «не знаем, чьё
  помещение». Иначе дыра в данных и осознанный выбор выглядят одинаково.
- **М-12. Номера присваиваются сразу всем 31, имя карточки не переписывается**
  (решение агента 10.09.2026). Порядок: по дате заведения карточки, при
  совпадении — по серийнику. 25 кофейных → K-001…K-025, 5 снековых →
  S-001…S-005, один автомат напитков → D-001.
  **Показываем составным именем:** `K-004 · KIUT Библиотека`, вторая часть из
  «Где стоит», обновляется сама при переезде.
  **Почему не ждать наклеек.** Имя карточки уже врёт: автомат «KARDIO Life» с
  08.09.2026 стоит на точке CardioLife — назван по СТАРОМУ месту. «American
  hospital» и место «American Hospital» разошлись регистром. Каждый переезд
  добавляет такую ложь. В системе номер стоит сразу, наклейка догоняет — ровно
  как у узлов, где 375 единиц пронумерованы, а очередь «наклеить номер» идёт
  своим ходом.
  **Когда наклейка проверена**, собственное имя карточки убирается совсем:
  личность автомата — номер, место — из «Где стоит».
