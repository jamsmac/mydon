# Развёртывание MYDON на MYDON/OS

**Сервер:** Hetzner (Helsinki) + Tailscale, `100.81.197.68`.
**Состояние на 2026-07-26 (замер):** 4 ядра / 7.6 ГБ RAM / 38 ГБ диск,
занято 25 ГБ (70%), свободно 11 ГБ, нагрузка 0.24, работает 13 контейнеров.
Docker есть, Node на хосте НЕ установлен — поэтому разворачиваем контейнерами.

Портов наружу не открываем (ТЗ §6): Core слушает `127.0.0.1`, бот работает
через long polling. Доступ — только через Tailscale.

---

## Перед первым запуском

1. Заполнить на сервере файл `.env` рядом с репозиторием:

```
POSTGRES_PASSWORD=<длинный пароль>
TELEGRAM_BOT_TOKEN=<токен бота>
TELEGRAM_ALLOWED_CHAT_IDS=<твой chat_id>
INGEST_KEY=<случайный ключ для приёма внешних событий>
SERVICE_TOKEN=<случайный токен: openssl rand -hex 32>
AGENT_AUTONOMY_MAX=T0
AGENTS_SCHEDULES_PAUSED=1
```

`SERVICE_TOKEN` обязателен. Core отклоняет любую запись (POST/PATCH/PUT/DELETE)
без него — 401, чтения при этом работают. Один и тот же токен из `.env` compose
раздаёт Core, панели, боту и агентам сразу, поэтому задавать его нужно в одном
месте, но ДО первого `up -d`: иначе панель и бот поднимутся с пустым токеном и
запись откажет, пока контейнеры не пересоздадут.

`AGENT_AUTONOMY_MAX=T0` и `AGENTS_SCHEDULES_PAUSED=1` — осознанные значения:
агенты только предлагают и не запускаются по расписанию, пока владелец не решит иначе.

Мозг, память и бюджет агентов включаются отдельными тумблерами `.env` —
их карта и сценарии в `docs/AGENTS_ACTIVATION.md`. Все они уже прокинуты в
контейнер `mydon-agents` (`deploy/docker-compose.yml`) и по умолчанию спят.

## Мозг помощника: подписка Claude или API-ключ

Помощник (панель и бот) понимает свободные вопросы, если задан хотя бы один
способ входа. Оба вписываются в тот же `.env` (значения вносит только владелец):

```
CLAUDE_CODE_OAUTH_TOKEN=<токен подписки — команда: claude setup-token>
ANTHROPIC_API_KEY=<платный API-ключ с console.anthropic.com>
```

- **Подписка** — та же, что у Claude Code на Маке, отдельно не оплачивается.
  Токен выдаёт команда `claude setup-token` (запускается на Маке, вход через
  браузер; токен действует год). Расход идёт в лимиты подписки.
- **API-ключ** — платный, поштучно за запросы. Нужен ТОЛЬКО для документов
  (Excel/Word-отчёты агентов): их делают серверные навыки Anthropic, которых
  в подписке нет. Для вопросов-ответов помощника не обязателен.
- Заданы **оба** — вопросы идут через подписку, а при её сбое или исчерпании
  лимита незаметно отвечает API-ключ.

После правки `.env` перезапустить панель и бота:

```bash
cd /opt/mydon-app && docker compose -f deploy/docker-compose.yml --env-file .env up -d mydon-cc mydon-bot
```

2. Проверить свободное место: нужно ~1.5 ГБ на образ и базу. Сейчас 11 ГБ — хватает.


замолчит вместе с ним.

## Автодеплой (телефон-цикл)

С 2026-07-30 сервер сам выкатывает изменения — чтобы владелец мог ставить задачи
с телефона (claude.ai/code), а принятые в `main` изменения попадали на живой
сервер без Мака.

**Как работает.** systemd-таймер `mydon-autodeploy` каждые 30 секунд запускает
`deploy/auto-deploy.sh` на сервере. Скрипт тянет `main` из GitHub read-only
deploy-ключом; если появился новый коммит — делает `pg_dump` базы, обновляет код,
пересобирает образ (`docker compose up -d --build`), применяет миграции и
проверяет health. Замок `flock` не даёт двум деплоям идти разом.

**Сколько ждать.** Раньше любой коммит стоил ~5 минут полной пересборки; теперь:

| Что изменилось в коммите | Что делает деплой | Время |
|---|---|---|
| только `data/`, `docs/`, `*.md` | `git reset`, и всё | ~5 с |
| код одного приложения | пересборка только его (кеш turbo), рестарт | ~40 с |
| зависимости, Dockerfile, схема БД | полная сборка, миграции, рестарт | ~5 мин |

Держится это на трёх вещах: сиды и выгрузки приезжают в контейнер **томом**
`../data:/app/data:ro` (в образе их нет — см. `.dockerignore`), кеш turbo живёт
между сборками через BuildKit cache mount, а шаг 0 скрипта распознаёт коммиты
«только данные/документы» и пропускает сборку. Правило узкое: любой файл вне
трёх путей — полный деплой; пустой список изменений (сбой `git diff`) — тоже
полный деплой, потому что пропустить сборку по неизвестному диффу опаснее.

**Обновить только данные** (после мержа сида): дождаться тика таймера и звать
импорт — пересборки не будет.
```
journalctl -u mydon-autodeploy -n 5 --no-pager   # «только данные/документы»
docker compose -f deploy/docker-compose.yml --env-file .env exec -T mydon-core \
  node tools/import-globerent-registry.mjs
```

**Ничего наружу.** Вебхуков нет, портов в интернет не открывали. Сервер сам
инициирует соединение к GitHub. Панель по-прежнему доступна только в Tailscale.

**Первичная настройка:** `deploy/setup-autodeploy.sh` на сервере (создаёт
deploy-ключ, делает `/opt/mydon-app` git-репозиторием `main`, включает таймер).
Публичную часть ключа один раз добавить в GitHub → Deploy keys (read-only).

**Наблюдать/управлять:**
```
journalctl -u mydon-autodeploy -n 50        # что делал автодеплой
systemctl list-timers mydon-autodeploy      # когда следующий тик
systemctl stop mydon-autodeploy.timer       # временно выключить
```
Бэкапы перед миграциями: `/opt/backups/mydon-autodeploy/pre_*.sql.gz` (последние 10).

## Пошагово: подключиться к серверу и выкатить

Порядок для случая «PR смержен в `main`, надо чтобы это заработало в поле».
Занимает 5–10 минут, из них большая часть — ожидание сборки.

**Главное, что надо знать заранее:** автодеплой выкатывает **код**, но
**`.env` не трогает никогда** (`auto-deploy.sh`: `git clean -fd -e '.env*'`).
Секреты не в git, и подставить их деплою неоткуда. Поэтому любой PR, который
добавил переменную окружения, требует ручного шага — иначе контейнер поднимется
с пустым значением и промолчит.

### 1. Подключиться

Сервер закрыт: портов наружу нет, вход только через Tailscale.

```bash
tailscale status | grep mydon      # видно ли машину из сети
ssh root@100.81.197.68             # тот же адрес, что по умолчанию в deploy.sh
cd /opt/mydon-app                  # НЕ /opt/mydon — там инфраструктура MYDON/OS
```

Если `tailscale status` пуст — сначала `tailscale up` на своей машине.

### 2. Посмотреть, что автодеплой уже сделал

```bash
git log --oneline -3                                  # на каком коммите сервер
journalctl -u mydon-autodeploy -n 30 --no-pager       # чем кончился последний тик
systemctl list-timers mydon-autodeploy --no-pager     # когда следующий (тик 30 с)
```

Строка `деплой ok: <sha>` означает, что код уже на сервере и здоровье проверено.
Ждать нечего — переходить к шагу 3. Строка `ОШИБКА` означает, что контейнеры
переключены, а health не поднялся: смотреть `docker logs --tail 50 mydon-core`
до того, как что-то менять дальше.

Если сервер отстал от `main` и таймер молчит — запустить деплой руками:

```bash
systemctl start mydon-autodeploy.service && journalctl -u mydon-autodeploy -f
```

### 3. Дописать переменные, которых у сервера ещё нет

Автодеплой их не принесёт (см. выше). Сверять `.env` с `.env.example`:

```bash
comm -23 \
  <(grep -oE '^[A-Z_]+=' .env.example | sort -u) \
  <(grep -oE '^[A-Z_]+=' .env         | sort -u)
```

Вывод — имена переменных, которых в боевом `.env` нет. Для полевого контура
(PR #111) их четыре, и все четыре дописываются так:

```bash
cp .env .env.bak.$(date +%F)                      # откатиться будет чем

# Перец приглашений. Генерируется ЗДЕСЬ, как остальные секреты. Пустой перец
# Core не роняет осознанно — поэтому пропажа тихая: приглашения хешировались
# бы без перца. Менять позже нельзя: смена гасит все ВЫДАННЫЕ приглашения.
grep -q '^INVITE_PEPPER=.' .env || printf 'INVITE_PEPPER=%s\n' "$(openssl rand -hex 32)" >> .env

# Привязка сотрудника по @username. Ник в Telegram освобождается после смены,
# и занявший его получит чужую карточку. Ставим "0": штатный путь — приглашение.
# Цена решения: сотрудник, чья карточка заведена с ником, но ещё не связана с
# Telegram, без приглашения не войдёт. Это и есть намерение, а не побочный эффект.
grep -q '^STAFF_LINK_BY_USERNAME=' .env || echo 'STAFF_LINK_BY_USERNAME=0' >> .env

# Имя бота без @ — панель собирает из него ссылку-приглашение.
grep -q '^TELEGRAM_BOT_USERNAME=.' .env || echo 'TELEGRAM_BOT_USERNAME=<имя_бота>' >> .env

# Монитор графиков: 06:00, ДО дайджеста сотрудникам (07:00).
grep -q '^MAINTENANCE_MONITOR_CRON=' .env || echo 'MAINTENANCE_MONITOR_CRON=0 6 * * *' >> .env

chmod 600 .env
grep -c '^[A-Z_]*=' .env        # столько строк стало — значения не печатаем
```

`TELEGRAM_BOT_USERNAME` — единственная, куда надо вписать значение руками
(имя бота без `@`). Остальные три самодостаточны.

### 4. Перезапустить то, что читает изменившиеся переменные

`docker compose` перечисляет окружение явно, поэтому новые значения попадают
в контейнер только при пересоздании. Рестарт (`restart`) не годится — он
оставляет старое окружение.

```bash
docker compose -f deploy/docker-compose.yml --env-file .env up -d \
  mydon-core mydon-cc mydon-bot mydon-agents
```

### 5. Проверить

```bash
docker ps --filter name=mydon- --format '{{.Names}}: {{.Status}}'
docker compose -f deploy/docker-compose.yml --env-file .env exec -T mydon-core \
  node -e 'fetch("http://127.0.0.1:3001/health").then(r=>r.json()).then(d=>console.log(d))'

# Перец доехал? Печатаем длину, а не значение.
docker compose -f deploy/docker-compose.yml --env-file .env exec -T mydon-core \
  node -e 'console.log("INVITE_PEPPER length:", (process.env.INVITE_PEPPER||"").length)'

docker logs --tail 20 mydon-bot      # «MYDON Bot запущен»
docker logs --tail 20 mydon-agents   # среди мониторов — монитор графиков
```

Длина перца `0` означает, что шаг 3 или 4 не сработал: возвращаться к ним,
дальше не идти.

### 6. Завести нормативы обслуживания

Без них раздел «Графики» пуст: система знает, как считать срок, и не знает,
от чего. Числа владельца уже в коде — команда раскладывает их на весь парк,
различая типы автоматов: кофейным (привязанным к кофейной точке) мойка миксера
раз в 10 дней и фильтр воды раз в 45, **всем** — плановое ТО раз в 90. Снеку
мойка миксера не заводится: у него нет ни миксера, ни фильтра, и такой график
краснел бы за работу, которой не существует. Идемпотентно, правки владельца
по отдельным автоматам переживает.

```bash
docker compose -f deploy/docker-compose.yml --env-file .env exec -T mydon-core \
  node tools/apply-maintenance-norms.mjs --dry-run    # посмотреть, что будет
docker compose -f deploy/docker-compose.yml --env-file .env exec -T mydon-core \
  node tools/apply-maintenance-norms.mjs              # завести
```

Проверить: панель → **Обслуживание** → раздел «Графики». Все строки должны быть
🟢 с датой через 10/45/90 дней, а не 🔴: сроки считаются от дня заведения.

### 7. Подключить сотрудников

Приглашение одноразовое, действует 24 часа (`INVITE_TTL_HOURS`), гасится
первым входом. Выдаётся в панели: **Команда** → карточка человека → блок
«Доступ» → «Выдать ссылку для входа»; ссылка показывается **один раз**. Тот же
путь есть у владельца в боте.

Ссылка вида `https://t.me/<бот>?start=inv_…` отправляется человеку **лично**.
В группу нельзя: первый, кто её откроет, и станет этим сотрудником.

После входа проверить в боте у самого сотрудника: `/start` → внизу экрана
постоянное меню, «📋 Мои задачи» отвечает списком, «🗓 Графики» — тем, что
завёл шаг 6.

### Если что-то пошло не так

```bash
ls -1t /opt/backups/mydon-autodeploy/pre_*.sql.gz | head -3   # дампы до миграций
git log --oneline -5                                          # куда откатываться
docker compose -f deploy/docker-compose.yml --env-file .env logs --tail 100 mydon-core
```

Откат кода — `git reset --hard <sha>` плюс пересборка тем же `up -d --build`;
таймер автодеплоя при этом надо остановить (`systemctl stop
mydon-autodeploy.timer`), иначе следующий тик вернёт `main` обратно.
