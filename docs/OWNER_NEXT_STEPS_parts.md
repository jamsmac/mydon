      `docker compose -f deploy/docker-compose.yml --env-file .env exec -T mydon-core node tools/apply-passport-fields.mjs --dry-run`,

- [ ] **Кофейные автоматы должны иметь карточку `kind=coffee`** (панель → карточка автомата → вид). Автозаведение
      берёт только их.
- [ ] Автозаведение узлов: `… exec -T mydon-core node tools/provision-parts.mjs --dry-run` — посмотреть план
      (на каждый кофейный автомат: 4 миксера, 1 гриндер, 1 варка, 8 бункеров, 1 фильтр; бункеры получают

      Повторный прогон ничего не дублирует. Узлам, которые бэкфилл 0084 восстановил из журнала БЕЗ номера
      (миксеры, гриндеры, варки), тот же прогон присваивает номер и ставит их в очередь наклеек — строки «№ …».

      работы («Завести N узлов и присвоить M номеров»). Состав правится в панели: Система → Настройки → `PARTS_TEMPLATE_COFFEE`.
- [ ] Проверить в панели `/parts`: узлов ≈ 25 × 15 = 375, все «наклеить номер». Если у кого-то из миксеров уже

## 3. Наклейки и права (неделя 1)

- [ ] Роли: у Рустама/Бехруза должны стоять `technician` / `operator` / `storekeeper` — права `parts.number`,
      `parts.move`, `parts.count` идут из ролей (`packages/shared/src/roles.ts`). В боте появятся пункты
      «🔢 Номера узлов», «🚿 Помыл узлы», «🗂 Инвентаризация узлов».
- [ ] Напечатать наклейки по списку `/parts` (фильтр «наклеить») — формат `M-001`, `G-001`, `B-001`,
      `H-27-3`, `F-001`.
- [ ] Сотрудники проходят очередь: бот «🔢 Номера узлов» → «Наклеил» / «Другой номер» по одному;
      либо панель `/parts/queue`. Пропуск ничего не запоминает — узел вернётся.
- [ ] Каждый понедельник 08:30 агент `vendhub-ops` (навык `parts-audit`) кладёт во Входящие одну задачу:
      сколько ждут наклейки, без номера, неизвестно где, без тары, без фото, что зависло на мойке. Агент
      должен быть `active` (он и так active).

## 4. Замена и мойка — новый порядок работы

- [ ] Замена миксера/бункера/варки: бот «🔧 Замена детали» → автомат → узел → **какой снял (по номеру)** →
      куда увёз (мойка/склад/ремонт) → запасной со склада или «новый» → причина. Записывается одной транзакцией.
- [ ] На базе после мойки: «🚿 Помыл узлы» → «Помыл» у узла (уходит на сушку) → позже «На склад».
      Сушку можно отключить: `PARTS_DRYING_STAGE=0` → сразу склад.
- [ ] Задачи ТО от монитора теперь называют узлы: «Стоят: M-017 (№1), M-018 (№2)…» — проверь на первой задаче.

## 5. Первая инвентаризация узлов (склад, мойка)

- [ ] Взвесить пустые бункеры без тары — тара вносится на карточке узла (`/parts/<id>` → «Тара, г»); без неё
      возврат не приходуется (очередь «без тары»).
- [ ] Бот «🗂 Инвентаризация узлов» → склад → по одному: вид → номер с наклейки → серийник → **фото** (или
      причина). «Закончить» даёт сводку. Обрыв связи не страшен — сессия продолжается тем же пунктом.
- [ ] Панель `/parts/count` → сессия → «Применить сессию»: найденные подтверждены, новые заведены,
      не найденные уйдут в «неизвестно где» (найдутся на следующей инвентаризации). Ошибся — «Откатить обратной сессией».
- [ ] Повторить для мойки и сушки. Фото обязательно по умолчанию (`PARTS_COUNT_PHOTO_REQUIRED=1`).

## 6. Возврат бункеров и списание заливок (кофе)

- [ ] Ингредиенты кофе должны быть связаны с карточками склада (`coffee_ingredient.entity_id`) — иначе возврат
      запишется, но не оприходуется («у ингредиента нет карточки склада»). Проверить: панель → Кофе → ингредиент →
      карточка реестра.
- [ ] Склад приёма: у склада в реестре поставить признак «приём по умолчанию» (если складов несколько).
- [ ] Возврат из группы «1. 027. 787» теперь отвечает: «📦 На склад: H-27-1: +377 г Кофе зерновой» или
      «⚠️ Не оприходовано — H-5-3: нет тары». Список непроведённых: `GET /coffee/container-return/unposted`
      (в панели — метка «не оприходовано» у возврата со ссылкой на карточку узла).
- [ ] Списание заливкой включено (`COFFEE_REFILL_CONSUMES=1`), но только по точным данным: число пачек × вес пачки
      (вес пачки — на карточке ингредиента) или веса «до/после». Заливки без данных — `GET /coffee/refill/unconsumed`.
      Не хочешь пока — выключи тумблер в Система → Настройки.
