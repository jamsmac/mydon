# Кофе-бункеры: как работаем после перехода на бота

Группа «VENDING SERVICE» больше не нужна для учёта: её история (с декабря 2025)
импортирована в MYDON, а текущие данные сотрудники вносят Telegram-боту.
Форматы — те же, к которым все привыкли.

## Сотруднику: четыре действия в боте

1. **Заливка бункера** — напиши боту «**бункер**» (или «засыпал»):
   бот спросит точку кнопкой → бункер (1–8, с подсказкой ингредиента) →
   вес после засыпки в граммах → сколько упаковок → номер набора (1–27,
   можно «-»). Дата ставится сама — сегодняшняя.

2. **Остатки при возврате наборов** — просто пришли то же сообщение,
   что раньше писал в тему «Остатки с бункеров», без команд:

   ```
   Кпп остатки
   1. 026. 1119
   2. 019. 1944
   3. 016. 1231
   ```

   Формат «позиция. набор. вес (брутто, с тарой)». Первой строкой можно
   точку. Бот запишет каждую строку и ответит сводкой; кривые строки
   покажет отдельно — их надо проверить глазами.

3. **Вода, стаканчики, крышки** — напиши «**вода**»: бот спросит точку
   кнопкой, потом три числа одним сообщением, например «2 100 100»
   (вода, стаканчики, крышки — в этом порядке). Повторная отправка за
   день перезаписывает, а не дублирует.

4. **Мойка** — напиши «**помыл**»: точка кнопкой → бункер (или вся
   машина) → готово.

Отменить любой шаг — слово «отмена». Список команд — «привет».

## Владельцу

- **«расход кофе»** боту — расход по наборам за 30 дней: граммы,
  себестоимость, топ точек.
- **Утренний брифинг (07:30)** сам подсветит недоливы, аномалии расхода
  и просроченную мойку.
- **Панель** → VendHub → Кофе-бункеры:
  - *Таблица* — последняя заливка каждого бункера (та самая «Таблица бункеров»);
  - *Журнал* — вся история заливок и возвратов с фильтром по точке;
  - *Сверка* — фактический расход (заливка − возврат через тару) против
    ожидания из продаж; аномалия = возможные потери, из строки можно
    создать задачу технику;
  - *Настройки* — цены ингредиентов (для себестоимости), тара наборов,
    эталонные веса, расписание мойки, привязка точек к аппаратам и
    история размещений.

## Как считается расход (для понимания цифр)

Расход = **нетто заливки − нетто возврата** одного и того же набора на
одной позиции; нетто — вес минус тара набора (27×8 калибровок в базе).
Если тара не калибрована или возврат тяжелее заливки — расход честно
показывается как «не посчитать», а не нулём. Ожидание для сверки —
продажи × рецепты напитков.

## Правила данных

- Ничего не попадает в учёт мимо согласования или бота: импорты истории
  требуют «Одобрить» владельца.
- Неизвестное значение — null/«—», а не ноль: пустая ячейка честнее
  выдуманной.
- Часовой пояс всех дат — Asia/Tashkent.
